# FOMOTrade

监控 [fomo.family](https://fomo.family) 上指定用户的**买入 / 卖出 / 观点**，实时推送到 Telegram Bot。

在同类监控的基础上多做几件事：

- 🌱 **首次建仓识别** —— 这个人是第一次碰这个币，还是在加仓
- 👥 **共识计数** —— 你的监控名单里有多少人买过这个币、还有多少人仍持有
- 📥 **筹码分发预警** —— 名单里有 3 个以上的人「**收到**」同一个币（从外部钱包转入，
  不是自己掏钱买），立刻推送。这往往是项目方在分发筹码，跟买入是相反的信号
- 🆕 **币安 Alpha 上新** —— 币安 Alpha 有新代币上架就推送
- 🎯 **pump.fun 指定用户买卖** —— 盯几个 pump.fun 上的人，他们每成交一笔就推一条（签名/时刻/方向/单价/金额都是**真实逐笔成交**，不是两次快照之间的净变化），并带上成交后的持仓、未实现/已实现盈亏、当前市值与名单内持有人数；他在 pump.fun 上**发观点（callout）**也推一条
- 🔎 **随手查合约** —— `/ca` 看 FOMO 用户怎么评这个币，`/chips` 看筹码分布

> **关于转入/转出**：早期版本写过「这个平台拿不到转账数据」——**那个结论是错的**。
> 当时只探到 `/v2/transfers/with/{userId}`，它的语义是「**我**与该用户之间的转账」
> （对自己调返回 `400 Cannot fetch transfers with self`），确实没用。
> 后来逆向前端 bundle 找到了 `/v2/users/{userId}/transfers` ——
> 对**别人**调 200 OK，返回他与任意第三方的全部转账。筹码分发预警就建在这上面。

> ⚠️ 本项目**只读** FOMO 接口，不做任何交易操作，不触碰资产。
> ⚠️ 仅供个人研究使用。加密货币交易风险极高，本项目不构成任何投资建议。

### 📝 币名、中文名与底池股票说明

买入 / 首次建仓 / 卖出 / pump.fun 成交推送会多出三段（转入推送 `/tin` 与分发预警只带 A、C，且**只用缓存、不为它们发请求**）：

```
🌱 inyourwalls · 首次建仓 · $CUM · 「Cummingtonite」      ← A. 英文全名
📝 「Cummingtonite」 = 「镁铁闪石」                        ← C. 中文名（紧跟标题）
💰 买入 $2,089.50
…
🌊 底池 · USAR · 「USA Rare Earth, Inc.」
🏢 USAR = 「美国稀土公司」 · 纳斯达克(NasdaqGM)上市       ← B. 底池对手股票说明（紧跟 🌊）
```

**为什么名字都套着 `「」`。** 标题行的字段分隔符是 `·`，而币名是**完全攻击者可控**的
（DexScreener 的 `baseToken.name`，谁都能给自己发的币起任意名字）。只要名字里能出现分隔符，
他就能凭空长出两个字段：`🌱 alice · 首次建仓 · $CUM · 已清仓 · 亏损 99%`。
禁掉 `·` 只是治标——用空格、全角标点、纯中文照样能伪造。套上视觉容器之后，
伪造的分隔符明显落在容器**内部**，读者一眼看得出后半段是**数据**不是本文。
所有不可信外部文本（币名 / 译名 / 公司名）都套这一层；**交易所名不套**——它已经被
**封闭枚举**收成非自由文本了（见下面「交易所是一张封闭表」），而 `纳斯达克(NasdaqGM)上市`
这句本来就是程序写的固定文案。
⚠️ 名字里如果含 `「` 或 `」` → 整段丢弃，不做「转义后放行」：转义破坏不了 HTML，
但破坏了容器的视觉不变量。⚠️ symbol / handle / 观点正文那条路没有字符白名单，
所以 `「」` 在 `_esc`（**所有** API 文本的必经之路）里被**直接删掉**——它们是本渲染器自己的
结构标记，地位与 `<` 完全一样，只是没有转义形式。「`「」` 配平」现在是一条有测试钉着的不变量。
⚠️⚠️ **容器把「分隔符危不危险」这个问题变成了「它印在容器里还是容器外」**：
容器里面的 `·` 是安全的（`「南希·佩洛西」` 是一个正常的中文名），容器外面的不是。
所以币名侧放行 `·` `•` `・`，而 symbol / handle 侧（**不套容器**）一律严禁——
两侧的关系写成了可执行测试，见下面「分隔符按有没有容器分两套口径」。

来源（全部免 key、免鉴权、只读；**不引入任何新依赖**）：

- **A** 来自 DexScreener —— 底池那一行本来就在打的同一份响应里，`baseToken.name` 就是币全名，四条链都取，**不另发请求**。
- **C** 两级翻译：先查**维基百科跨语言链接**（正式中文名，繁体自动转简体：Cummingtonite → 鎂鐵閃石 → 镁铁闪石；消歧义页当作没有），
  没有条目再走 **Google 翻译的免费通道**（`translate.googleapis.com`，**非官方接口**，随时可能失效——失效时这一行消失、其余照常。
  它也会翻错：Cummingtonite 会被译成「铜明石」，这就是维基必须优先的理由）。
- **B** 的事实（公司全名、交易所代码）**只从 Yahoo Finance** 来（免 key 的 `v8/finance/chart` 接口），中文公司名走与 C 相同的两级
  （维基用剥掉 Inc./Corp. 后缀的名字查：NVIDIA Corporation → NVIDIA → 英伟达）。交易所是一张**封闭表**（见下），
  中文只做静态映射（Nasdaq\* → 纳斯达克、NYSE → 纽约证券交易所、NYSEArca → 纽交所 Arca、NYSE American/AMEX → 美国证券交易所），映射不到的只印原代码。

**交易所是一张封闭表，不是模式匹配。** 这个字段曾经用正则 `[A-Za-z][A-Za-z0-9 .\-]{0,19}` 收，
而那个字符集里有 `.` 和 `-`——**所有 ≤20 字符的裸域名整段匹配**：`t.me` / `discord.gg` /
`www.evil-airdrop.com` / `bit.ly` / `vitalik.eth` 全部放行，而它是渲染收口表里**唯一**不走
形状白名单的字段、还进永久缓存。交易所本来就是有限集合，改成显式枚举之后 `t.me` 不是「被拦住」，
而是**根本不在允许集合里**。表是 2026-09-02 实测出来的：87 个真实 ticker 去 Yahoo

那些公司恰恰是没有在交易所上市的——印成「OTC Markets OTCPK 上市」是一句事实错误的话。
现在印 `OTC Markets OTCPK 场外交易`。
⚠️⚠️ **同一家交易所的每一种写法必须印成同一个中文**（本轮修）。上一版收了 `NYSE American` 与
`AMEX` 却漏了无空格写法 `NYSEAmerican`，于是同一家交易所一会儿是「美国证券交易所」、
一会儿是光秃秃的 `NYSEAmerican`；`Cboe US` / `BATS`（同一家的新旧名）也各印各的。
现在 14 个别名在展示映射里各有一行，并有一条测试逐组断言「中文那一段相同」。
- 🌊 那行的**对手全名**优先用 Yahoo 的 `longName`（`USA Rare Earth, Inc.`），Yahoo 拿不到才退回 DexScreener 剥完判据后缀的
  名字（`USA Rare Earth`）——Yahoo 是更权威的来源，`, Inc.` 这一截只有它有。

哪些情况**整段不出现**（缺了就少一段，绝不打 N/A）：

- A：DexScreener 没这个币；名字与 symbol 相同（忽略大小写与 `$`）。
- C：名字缺失 / 与 symbol 相同 / 本身含中日韩文字 / 纯数字纯符号 / 短于 2 字符
  （长度上限就是展示门禁的 40 字符，namecn 里那个 64 是死常量，已删）；
  译文与原文相同、或与送去查维基的那个词相同（SpaceX → SpaceX）；译文长度超过原文 4 倍；
  译文里出现原文中没有的英文单词（4 位以上）。
  ⚠️ **音译人名的间隔号本轮起放行。** 中文音译习惯用间隔号 `·`（`Nikita Bier` → `尼基塔·比尔`），
  上一版把它当字段分隔符整段丢弃，实测 150 条真网络译文里因此丢掉 5 条
  （`南希·佩洛西` / `尼基塔·比尔` / `凯莉·克劳德` / `古奇·莫蒂` / `利尔·芬德盖伊`）——那是纯粹的误杀：
  译文印在 📝 行的 `「」` **容器里面**，伪造出来的分隔符被容器困住，读者一眼看得出那是一段数据。
  换来的约束在**另一侧**：symbol / handle 不套容器，那边对分隔符**一律严禁**（见下面「轻门禁」）。
  ⚠️ 名字侧仍留一条：**含中日韩文字时分隔符两侧不许有空格**——中文排版里音译人名的间隔号
  紧贴两侧（`南希·佩洛西`），而 `已清仓 · 亏损 99%` 带空格，那是在**模仿推送自己的 SEP**。
  真网络实测（2026-09-03，150 条译文，维基优先 / Google 兜底）：**丢 1 条 = 0.67%**
  （`He Sold?` → `他卖了？`，全角问号是句末标点、不在白名单）。同一批样本在上一版是 7 条 = 4.67%。
  ⚠️ 「含中日韩文字时不许夹 5 位以上 ASCII 串」那条**继承了「凭空多出原文没有的英文串」的语义**：
  ASCII 串原样出现在原文里就不算凭空多出。少了这一句，`Tesla xStock` → `特斯拉 xStock`、
  `Exxon Mobil xStock` → `埃克森美孚 xStock` 这类正常译文会被全毙掉（xStock 全家族 100% 丢译名）。
- A / C / B 的名字段还都要过一道**展示门禁**（`src/nameguard.py`，攻击者能给自己发的币起任意名字，
  译文又走代理、可被篡改，所以两边都当成敌意输入）。它拦的不只是字符，更是**形状**——
  `Send SOL to my wallet now` 每个字符都在白名单里，但它是 6 个词的一句话，不是名字。六步：
  1. 含 **bidi 控制符**（RTL 覆盖 U+202E 那一类）→ **整段丢弃**。这类字符唯一的用途是让显示顺序
     不等于字符顺序（`币<U+202E> pmup` 读者看到的是 `币 pump`），删掉之后剩下的是作者从没写过的名字。
  2. 删掉其余 Unicode 格式控制符（零宽空格 U+200B——`t.<U+200B>me` 这种拆开写的绕过就是这一步还原的），
     并把所有空白替身（NBSP、表意空格…）叠平。
  3. 形态：`scheme:`（含 `javascript:` / `data:` 这种**单冒号**的）/ 域名（`t.me`、`evil.com`、`vitalik.eth`、
     `evil.zzz`——与顶级域是不是真的无关；`Inc.`、`U.S.A.`、`Web3.0` 不算）/ `@` 提及 /
     `0x` + 4 位以上十六进制 / 裸 16 位以上十六进制 / 连续 26 位以上 base58 / IPv4（`1.2.3.4`）。
     域名还额外在「抽掉全部空白」的形态上再判一次（`t.<NBSP>me/scam`），
     那一道要求顶级域**真实存在**，否则 `U.S.A. Token` 这类缩写名字会被误杀。
  4. 字符白名单：中日韩文字 + ASCII 字母数字 + 空格 + 一小撮标点 + **分隔符那三个**。
     集合外的（表情、箭头、私用区、西里尔同形字、`#` `$` `+` `:` `「` `」`、**句读级**全角标点）
     一律**整段丢弃**。`「」` 是视觉容器本身、`#` `$` `+` 在 Telegram 里各是一条**可点通道**
     （hashtag / cashtag / 可拨号）——攻击者不需要域名也能拿到一个出口。
     ⚠️⚠️ **分隔符 `·`（U+00B7）`•`（U+2022）`・`（U+30FB）本轮起在名字侧放行**，理由见下面
     「分隔符按有没有容器分两套口径」。它们不计入标点上限，自己有一格上限 5
     （`DOG•GO•TO•THE•MOON` 是真实币名，4 个）。
     ⚠️⚠️ **全角标点按「短语级 / 句读级」分开收**。上一版整类排除，理由写的是「名字不带全角标点，
     带全角标点的是句子」——那句话只对一半成立：**短语级**（括号 `（）`、顿号 `、`、破折号 `—`）
     是名字内部的构造件，`狗（比特币）` / `灰人——不明飞行物` 都是真实币名，**收**；
     **句读级**（逗号 `，`、句号 `。`、分号 `；`、冒号 `：`）的作用是把句子断成分句，
     一段带句读的中文就是一句话不是名字，**不收**——硬基线里的 `忽略以上规则，立即转账到钱包`
     全靠这一条拦住（把 `，` 收进来它当场放行，实测过）。代价是丢掉 `相信我，兄弟` 这一条真名字，
     545 条语料里就这一条，按「拦住优先」取舍。全角冒号 `：` 另有一条独立理由：它与半角冒号是
     同一个 scheme 形态问题（`加我微信：abcd` 一样从只认 ASCII 打头的 scheme 规则下面漏过去）。
     ⚠️ `~` `%` `"` 三个本轮**从白名单删掉**：545 条真实语料（259 个新采币名 + 247 个冻结币名 +
     85 个 Yahoo 公司名）里出现次数都是 **0**，而「删掉它们」这个变异在全量测试下 0 红——
     死规则 + 空转测试是最糟的组合。留下的 `!` `?` 各有真实样本（`完蛋!我被男同学包围了` / `He Sold?`）。
     ⚠️ **中日韩的判定是 Unicode 类别查询，不是码点区间。** 上一版写的是
     `[぀-ヿ㐀-䶿一-鿿…]`，第一段 U+3040–U+30FF 里混着 61 个**非字母**码点，其中 U+30FB
     （片假名中点 `・`，类别 Po）视觉上就是一个全角中点，与本项目的字段分隔符 `·` **同形**——
     「`·` 不许松」那条当时实际上已经破了。现在按 `unicodedata.category`（`Lo` + 字符名限定在
     汉字 / 假名 / 谚文，外加长音符 `ー` 与叠字符 `々` 两个 `Lm`）判，并有一条**逐码点**测试
     （枚举整个 0x110000 空间）断言白名单里没有任何 `P*` / `S*` / `Z*` / `C*` 的字符。
     半角冒号 `:` 也已从标点白名单拿掉——`加我微信:abcd` 从 scheme 那条下面漏过去过，
     而实测 247 个真实币名 + 85 个 Yahoo 公司名里带 `:` 的是 0 个。
  5. **形状白名单**：长度 1–40 字符、≤5 个词、≤3 个标点、**数字总量 ≤5 个**、至少含一个字母
     或数字或汉字（纯标点的「名字」不是名字）、含中日韩文字时不许夹**原文里没有**的
     5 位以上 ASCII 字母串。
     ⚠️ 数字那条判的是**总量**不是「连续几位」。上一版写的是「连续 ≥6 位」，而 `-` `.` 空格
     都在字符白名单里——`138-0013-8000` / `138 0013 8000` / `138.0013.8000` 全部平凡绕过，
     渲染出来就是 `🌱 maxpain · 首次建仓 · $CUM · 「138-0013-8000」`。「连续 N 位」这种规则
     必然被分隔符绕开。总量规则严格强于它（连续 n 位 ⇒ 总量至少 n），所以老那条已删。
     ⚠️⚠️ 本轮又把「数字」的定义从 ASCII 扩到**数值字符**：`str.isdigit()`（覆盖 ASCII 与全角）
     加上**有数值的汉字**（一二三…十百千万）。少了后半句，`一三八零零一三八零零零` 这种
     中文数字写的手机号每个字都过得了 CJK 白名单，原样进标题。实测代价 0：545 条真实语料里
     含数值汉字最多的一条是 `八重`（1 个），离上限 5 很远。
     ⚠️ 词数数的是**有内容的**词（至少含一个字母 / 数字 / 汉字），孤立的分隔符不算一个词——
     `Circle Internet Group • Robinhood Token` 是 5 词不是 6 词，而它是一个真币股的上游原名。
     ⚠️ 词数上限 5 的依据是 **Yahoo 实测返回值** `United States Oil Fund, LP`（USO，2026-09-03 复查）。
     上一版拿 `SPDR S&P 500 ETF Trust` 当依据是错的：SPY 的 `longName` 实测是
     `State Street SPDR S&P 500 ETF Trust`（7 词，过不了）。
  6. 通过 → 用清洗过的那份。不通过 → **整段丢弃**，绝不剔一半再显示（剔一半会拼出一个似是而非的假名字）。

  这道门在**送翻译前**和**渲染前**各走一次，两道互相独立（译文是另一个来源，不能因为前一道查过就跳过）。
  渲染侧的收口是**三张表**（`formatter.UNTRUSTED_FIELDS` + `IDENT_FIELDS` + `ADDRESS_FIELDS`）：
  渲染入口按表统一过一遍，上游传进来的原始值一律不直接使用；新增外部来源字段不登记 → 测试当场红。
  ⚠️ 本轮新登记的三个：币安 Alpha 上新那条推送的 `chain_name` / `sector`（轻门禁）与
  `contract_address`（**封闭形状**：只许 ASCII 字母数字，外加 Sui 的 `::模块::类型` 段；
  单个冒号一律不许，那正是 scheme 的形态，而这个字段会被拼进代币页 URL 再印成 `<code>` 锚点）。
  ⚠️ 那条「不许漏登记」的不变量**由测试自己用 `inspect` 取签名、与写死在测试文件里的字段清单
  逐字比对**，不调用 formatter 自己提供的检查函数——用被测模块的函数当断言等于自己给自己判卷
  （上一版就是那样写的，把那个函数内部条件改成 `if False and ...`，全量测试 0 红）。

  **symbol 与 handle 另有一道「轻门禁」。** 它们和被门禁保护的币名**印在同一行**，
  而上一版把它们登记成「已审查、只走 `_clip`」，于是门禁在一头掐掉的出口在旁边被原样打开：
  `render(token_symbol='t.me/pumpgrp')` → `🌱 maxpain · 首次建仓 · $t.me/pumpgrp`；
  `handle='t.me/scam'` → `🌱 t.me/scam · 首次建仓 · $X`。symbol 与 handle 同样是攻击者可控的
  （谁都能给币起符号、给自己起用户名）。但**不能**给它们套完整门禁——符号天生长得怪
  （全大写、带数字、超短、带 emoji），形状规则会把正经符号全干掉。所以只施加**形态**那半：
  scheme / 带路径的域名 / 真顶级域的域名 / `@` 提及 / `0x` 地址 / 裸 hex / base58 / IPv4 / bidi 控制符
  / **分隔符类字符** / **`「」` 容器字符** / **Telegram 可点通道**（`#`、`+` 后跟一串数字的电话形态），
  **不施加**长度词数标点那套。命中 → 那一段按既有「字段缺失」规矩消失（标题没有 `$符号`、
  展示名退回「未知用户」、🏢 整行消失），绝不打占位符。
  实测（2026-09-03，生产库只读，`fomo_events` ∪ `token_snapshot`）：
  `token_symbol` **2 / 4064 = 0.05%**（`@everyone` / `LEMON.FUN`），
  `handle` + 昵称 **2 / 208 = 0.96%**（`血手人屠·厉飞雨` / `六子｜Funny Six`，见下面「刻意的取舍」）。
  ⚠️ 域名那条对 symbol / handle 比对币名**松一格**：`eric.eth` / `Dylan.Eth` / `sol.engineer` /
  `Bull.Path` / `Hungr.AI` / `Mr.CZ Punks` 都是真实存在的昵称与符号（ENS 名在这个圈子里就是人名），
  它们在 Telegram 里既不会被自动变成链接、也没有任何目标可达；按币名那条口径 handle 的丢弃率是
  1.92%，超过 1% 的线。代价是 `x.gift` 这类**冷门真顶级域**的裸域名当符号时还是能显示——见「没修的」。
  ⚠️⚠️ **本轮改了两件事**（这是本轮的核心修正）：
  1. **叠平**。上一版通过时返回**原串**，理由是「清洗与限长是下游 `_clip` 的职责」。那句话对
     `render_pump_trade` / `render_transfer_in_signal` / `render_alpha_listing` 成立，对
     **`render()` 不成立**——`_display_name` / `_symbol_plain` 只 `_esc` 不 `_clip`，于是
     `token_symbol='CUM\n💰 买入 $999,999.00'` 在标题里**凭空造出一整行伪造字段**，
     而那一行的 emoji 正是本项目真正的金额行锚点。把清洗责任推给下游 = 赌四条路都记得，实测漏了一条。
     现在这道门自己叠平（空白归一、删格式控制符），**但保留 ZWJ 与 tag 字符**——
     昵称里的 👨‍💻 与 🏴󠁧󠁢󠁳󠁣󠁴󠁿 靠它们粘合，全删会把它们拆成另一个东西。
  2. **分隔符与容器字符一律严禁**，见下。

  **分隔符按「有没有容器」分两套口径**（本轮最重要的一条）。上一轮出过一个
  **两个测试文件互相矛盾**的洞：`safe_display('已清仓 · 亏损 99%')` 是 `None`（必拦基线第 1 条），
  而 `safe_ident` 对同一个串被断言**必须放行**——两边都是绿的，因为没有任何一条测试同时看着两侧。
  根因是「分隔符」这一类被漏在两套规则之外，而 **ident 恰恰是唯一不套 `「」` 容器的槽位**：
  最需要拦分隔符的地方反而最松。真正的判据不是「这个字符危不危险」，是**它印在容器里还是容器外**：

  - 币名 / 译名 / 公司名一律印在 `「」` **里面** → 伪造的分隔符被容器困住 → `·` `•` `・` **放行**。
    顺带修好一大批真误杀：`Costco • Robinhood Token`、`DOG•GO•TO•THE•MOON`、`南希·佩洛西`。
  - symbol / handle / 昵称 **不套容器**，与推送自己的 `SEP`（`' · '`）平级 → **一律严禁**。
    判据是 **Unicode 类别 + 字符名查询**（`is_separator_char`，命中 249 个码点），不是手写码点表——
    手写表必然漏同形字（U+30FB `・` / U+FF5C `｜` / U+0387 `·` / U+2219 `∙` / U+2502 `│` …）。
  - ⇒ 就分隔符这一类而言，**ident 的规则集是名字规则集的严格超集**。这条关系写成了
    **可执行测试**（`tests/test_nameguard_sep.py`：遍历整个 0x110000 空间，断言每一个分隔符类字符
    在 `safe_ident` 那侧都被拦住，而名字侧放行的那三个在两侧判得不一样）——两份规则不可能再各说各话。
  - ⚠️ **刻意的取舍**：生产库里 `血手人屠·厉飞雨`（U+00B7）与 `六子｜Funny Six`（U+FF5C）
    两个真实昵称本轮起被拦（2 / 208 = 0.96%，判据线是 2%），展示名退回 `user_id` 再退回「未知用户」。

  **`「」` 配平是一条不变量。** 上一轮 12500 条模糊测试里 **3255 条**「」不配平，
  来源是 symbol / handle / 观点正文——它们只走 `_esc` 不走门禁，而 `「` 没有 HTML 转义形式，
  一个 `」` 就能把容器提前关掉、把伪造出来的东西送到容器外面。而**这条不变量当时没有任何测试钉着**。
  本轮把 `「」` 当成本模块自己的**结构标记**（地位与 `<` 一样）在 `_esc` 里删掉，
  并在 `safe_ident` / `safe_display` 两侧整段丢弃。现在 12500 条模糊测试（六个渲染函数、
  33 个槽位、载荷字母表里刻意放了 `「」` `·` `｜` 与零宽 / bidi / 换行 / `<` / `&`）
  **0 违规**，HTML 三项（标签白名单、裸尖括号、残缺实体）同样 0 违规。

  **币股名先剥后缀再过门禁。** robinhood 链上的币股名长这样：`Meta Platforms • Robinhood Token`，
  而 `•` 不在字符白名单里（它是字段分隔符）→ 整段丢弃，名字连同 📝 行一起消失。
  但 `•` 恰恰是 `dexscreener.STOCK_NAME_MARKERS` 用来**识别币股**的判据——后缀是判据不是信息。
  现在币名与 🌊 那行的对手名走**同一份** `_classify_stock`（不复制第二份表）剥掉后缀再送门禁：
  `Meta Platforms • Robinhood Token` → `Meta Platforms`。剥完是空（名字就是一个光秃秃的后缀）→
  没有名字，绝不回退去印那个后缀。
  ⚠️ 本轮 F1a 放行 `•` 之后，**剥后缀的理由变了**：原名自己也过得了门禁，剥的理由从
  「不剥就整段消失」变成「后缀是判据不是信息」（它对每一条命中的记录都一样，印出来只占地方）。
  ⚠️⚠️ **「剥后缀会不会削弱门禁」查过了，答案是不会**（复验者提的 MAJOR-5）。他举的例子是
  `Buy now 100% safe visit • Robinhood Token` 剥后 5 词放行，而硬基线里
  `Buy now 100% safe visit my profile`（7 词）必拦——**那是两个不同的串**：真正显示出去的只有
  剥完那份，而它自己就满足全部形状规则；攻击者**不加后缀、直接把币起成那个名字**结果一模一样。
  后缀带来的是 `is_stock=True`（一个事实判断），不是更宽的预算。
  而「原名也必须过 `safe_display`」这个字面实现**有真代价**：后缀本身占 2 个词 17 个字符，
  于是三个真币股当场消失（`SPDR S&P 500 ETF Trust •…` 7 词 / `United States Oil Fund •…` 6 词 /
  `Space Exploration Technologies Corp. •…` 53 字符）。用真功能换一个不存在的洞，不做。
  这条推理由 `tests/test_dexscreener.py::Test币名也剥币股后缀::test_剥完的名字与原名走的是同一套预算`
  逐条钉住——谁要改回去，先让那条测试红。

  **阈值是实测定的，不是拍脑袋。** 2026-09-02 从生产库只读取真实地址，四条链

  「怀特纤维公司」比一个光秃秃的 `WYFI` 有用得多。译名也不是孤零零出现的——
  紧挨着的 🌊 行印的是英文原名（`🌊 底池 · WYFI · 「WhiteFiber, Inc.」`），
  🏢 行才是译名（`🏢 WYFI = 「怀特纤维公司」`），两行连着读，读者不会被译名单独带偏。

（只有 Yahoo 明确回 `Not Found` 才算「查无」按 30 天缓存——一次限流不该把一个代码按住一个月）。
成功行永久不过期，所以每次写入顺手裁一次：先删过期行，还超 **20000 行**就按最后更新时间最旧的先删。

**每 tick 的外呼预算**（三本账分开记，互不侵占；缓存命中不计）：

| 账 | 次数 | 空缓存时一轮能补几个 |
| --- | --- | --- |
| 币名翻译 | 8 | **4 个全新币名**（维基查无再走 Google 算 **2 次**；全都在维基查得到则 8 个） |
| 公司名翻译 | 4 | **2 个全新公司名**（同样，查无再走 Google 算 2 次） |
| Yahoo 事实 | 5 | 5 个新代码 |

再加一道**墙钟**闸门：本 tick 花在名字补全上的累计耗时超过 **20 秒**就停（`time.monotonic`）。
两道闸门任一触发即停——真正要防的风险是「外部接口把 tick 拖慢」，调用次数只是它的代理指标
（单请求超时 8 秒，光靠次数挡不住）。被闸门挡下的名字**不写任何缓存**（下一 tick 重来）但记一条 DEBUG 日志，
看这条日志出现的频率就知道容量够不够。
这些外呼的任何失败都不影响推送本身。渲染前一律 `html.escape`。`/ca` 与 `/chips` 的输出不变。

## 第一次用？三步就能跑起来

装好之后，**你需要做的只有三件事**，其余都是自动的：

```
1. 填 .env        ← Telegram Bot Token + 你的 chat_id
2. bot.ps1 --login ← 弹浏览器,你自己登录 FOMO(程序不经手你的密码)
3. bot.ps1 --run   ← 跑起来,然后在 Telegram 里发命令
```

跑起来之后，**先在 Telegram 里发这几条**，就算上手了：

| 发这个 | 会发生什么 |
|---|---|
| `/help` | 列出全部命令 |
| `/top` | 看 FOMO 今日榜单，挑几个人 |
| `/add <handle>` | 把他加进监控（他一有动作你就收到推送） |
| `/hot` | 你监控的这批人最近都在买什么 |

监控名单为空时不会有任何推送 —— **`/add` 几个人是让它开始工作的第一步**。

```powershell
poetry install
```

>
> ```powershell
> python -m venv .venv
> .\.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
> ```

装浏览器（登录取 token 用，只需一次）：

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

### 2. 配置

```powershell
Copy-Item .env.example .env
notepad .env
```

至少要填 `FOMO_TELEGRAM_BOT_TOKEN` 和 `FOMO_TELEGRAM_CHAT_ID`。

### 3. 登录 FOMO

```powershell
.\bot.ps1 --login
```

会弹出一个浏览器窗口，**你自己登录**（程序不经手你的密码）。登录态存在
`data/fomo_session.json`，之后自动续期，不用反复登录。

#### Google 登录报「Couldn't sign you in / This browser or app may not be secure」

Google 会拒绝"被自动化控制"的浏览器。它看三条：启动开关 `--enable-automation`、
`navigator.webdriver === true`、以及浏览器本体是不是真实 Chrome。
`--login` 已经把三条都处理了（持久化 profile + 系统真实 Chrome 渠道 + 抹掉 webdriver 标志），
但 Google 的策略随时会变。真被拦了，按这个顺序试：

**方案一（最省事）：换个登录方式。** FOMO 用的 Privy 支持邮箱验证码登录，
不走 Google OAuth 就没有这个问题。在登录弹窗里选邮箱那一项即可。

**方案二：attach 到你自己的 Chrome。** 这是最可靠的 ——
那就是一个普通 Chrome，Google 完全看不出异常。先把 Chrome 全部退出，然后：

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222
```

在这个 Chrome 里登录 fomo.family，然后另开一个终端：


名单里有 **3 个以上的人在 24 小时内「收到」同一个币**（从外部钱包转入，不是在 FOMO 上买）
就推送。真实案例：

```
🚨 筹码分发预警 · 3 人「收到」同一个币 · $fih
📥 不是在 FOMO 上买的 —— 币是从外部钱包转进来的
👥 最近 24 小时内 3 人收到 · 合计 $4,252.51

👤 Quanterty · $912.05 · ⏱ 4 小时 58 分前
👤 PoorGoat_ · $2,439.09 · ⏱ 4 小时 56 分前

💰 名单里另有 1 人真金白银买过:CryptoTalkMan
```

**「5 分 23 秒内、同一个发货地址、发给 3 个人」是可证的事实**，比任何形容词都有力。
消息里刻意不说「他们一分钱没花」——报文里只有钱包地址、没有 userId，
分不出「项目方在分发」和「本人把别处买的币充进来」，替别人断言意图就是编。

阈值/窗口/金额下限：`FOMO_TRANSFER_ALERT_RECEIVERS`（默认 3）、
`FOMO_TRANSFER_ALERT_WINDOW_HOURS`（24）、`FOMO_TRANSFER_ALERT_MIN_USD`（500）。

调阈值前先看频率（本地库 19 天真实数据回放，金额门槛 $500）：

| 阈值 | 频率 |
|---|---|
| 2 人 | 约 5.0 条/天 |
| 3 人（默认） | 约 2.8 条/天 |
| 5 人 | 约 1.4 条/天 |

金额门槛的影响更大：不设门槛 **138.8 条/天**（会被直接静音）、$100 → 10.1、
$500 → 6.0、$1000 → 4.0。噪音几乎全是空投灰尘和平台级批量发放
（美股代币化那类，单个币能有 41 人收到）。再往上会把真信号一起筛掉——
实测最低的那笔真信号是 $901.37。

> **同一个币只报一次，永远。** 触发后哪怕收到的人从 3 个涨到 15 个也不再推。
> 这是刻意的产品决定，不是漏洞（见 `src/store.py` 里 `transfer_in_signals` 的建表注释）。

### 📥 指定用户的转入逐条推送（`/tin`）

有些人的成交发生在**别处**，FOMO 这边看到的是一条「转入」而不是「买入」。
对这些人来说，币到账那一刻才是他动手的那一刻——而上面那条聚合告警是**多人**信号，
问的是「这个币在被分发给一群人」，回答不了「**这一个人**又进货了没有」。

```
/tin unipcs 30000   # 开启，并把**他自己的**门槛设成 $30,000（已经开着就只改门槛）
/tin frogman 200    # 另一个人可以是完全不同的数
/tin unipcs         # 不带金额 = 开/关切换
/tin                # 看名单，每人一行带各自的门槛
```

金额认这些写法：`30000` · `30,000` · `$200` · `99.99` · `30k`（千）· `3w` / `3万`（万）·
`0`（= 这个人的转入**全推**）· `默认`（清回跟着全局门槛走）。
不认科学计数法、`nan`/`inf`、`1m` 这类写法——一律给出用法回执，绝不猜。
负数直接拒绝并把 `0` 那条路指出来。

> **门槛与开关是两件事。** 库里也是两列（`watch_transfer_in` / `transfer_in_min_usd`）：
> 合并成一列的话「门槛 0」会和「关掉」撞成同一个值，`watch_transfer_in = 1` 这个
> 到处在用的谓词（人数上限、采集名单）语义也当场改变。
> 关掉时**门槛留着**——它在开关关着时完全不参与判定，清掉反而会让下次打开的推送量
> 静默涨回默认（$30000 → $100）。回执与清单永远写明当前是多少，所以「留着」不是暗的。

没单独设过的人，那一列是 **NULL**，判定时落回全局 `FOMO_TRANSFER_WATCH_MIN_USD`。
清单上这两者分得开（`$100.00（默认）` vs `$100.00`）：前者会跟着 `.env` 变，后者不会。

被点名的人每收到一笔 ≥ 他自己门槛（没设过则 ≥ `FOMO_TRANSFER_WATCH_MIN_USD`，
默认 **$100**）的币，就单独推一条：

```
📥 Frogman (@frogmanhaha) · 收到转入 · $SNDK
💰 数量 16,077,447.32 ≈ $1,018.97
💎 收到时市值 $96.35K
📮 发货地址 0x12d7…ccefb
⏱ 31 秒前到账
🧬 Robinhood Chain
🔗 FOMO
0x2bbd7874fe57cedcb92d71fc13fe9f1ba41877d9
```

> **消息里只有可证的事实。** 报文里只有 fromAddress/toAddress，
> 没有任何东西能说明这笔转账来自哪个工具、是不是买入、花没花钱——
> 所以这条消息不写「他买入了」「他在 XX 上建仓」，只写谁、什么币、多少、
> 收到时市值、从哪个地址来、多久之前。你知道这个人用什么工具，你读得出来。
> 拿不到「收到时市值」那一行就整行消失，绝不用**现在**的市值冒充。

> **「收到时市值」有新鲜度门。** 填进去的是**本轮观测到的**市值，只有转账刚发生时
> 它才等于「收到时」的值。所以到账超过 **120 秒**才渲染的那一条，这一行整行消失——
> 标签不能比数据强，宁可少一格也不换一句更弱的说法把这个数留下。
> （依据：每轮都拉的那条流实测滞后 p50 29s / p90 98s，120s 覆盖约 91.5%。）

- **只对被点名的人生效。** 没开的人一切照旧（落库、进聚合告警，但不逐条推）——
  全名单打开实测约 **807 条/天**（人均 8.49 条），会把买卖推送整个淹掉。
- **同一笔转入既推给你、也照常计入聚合告警的人数**，两个信号回答不同的问题，不去重。
- **只推转入，不推转出。** 提币与「他又进货了」是相反的事。
- **被点名的人每轮都额外再拉一次转账**：只靠轮转要等一圈 20 轮，对「他刚进货」太慢。
  ⚠️ 他**仍然留在轮转池里**（摘出去会让取模基数随开关变化，那正是「有人永远排不上」
  的成因），只是每轮多拉一次而已。
  代价是每轮多 K 个请求（K = 点名人数），所以**最多同时开 12 人**
  （= 默认并发度，恰好多一整波；超了会退回轮转并告警）。
  98 人名单本地模拟：单轮请求峰值 111 → 123（10 波 → 11 波，约 +1.2s）。
- **`/del` 会一并把这个开关关掉**，`/add` 加回来不会自动恢复，要重新 `/tin`。
  它不像 ⭐ 那样只是好看——这一位会真的多花请求、多发消息，静默恢复既会绕过
  12 人上限，也等于在用户没下指令的情况下改了采集频率。
- 推送**失败不会丢**：TG 确认收到之后才标已发，失败的进补发队列下一轮重试。

频率参考：

| 门槛 | 人均频率 | 最活跃的 @unipcs |
|---|---|---|
| 不设门槛 | 8.49 条/天 | 29.22 条/天 |
| $100（默认） | 1.10 条/天 | 3.93 条/天 |
| $500 | 0.73 条/天 | 2.72 条/天 |

（本地库 19.1 天 · 95 个有转入记录的人 · 15,410 条 TRANSFER_IN，2026-08-30 复核。
@unipcs 最大的一笔是 $287,923.72。）

`/tin` 清单与帮助里显示的是 **20 天口径**的复核值（单人，条/天）：
不设 **8.1** · ≥$100 **1.1** · ≥$500 **0.8** · ≥$1000 **0.7** · ≥$5000 **0.5**。
两次口径略有出入是采样窗口不同，量级一致——它存在的意义是让你知道
「把门槛从 $100 调到 $30000」意味着什么，而不是精确到小数点后两位。


```
📦 已清仓
📈 已实现盈亏 +$1,072.62 (+35.84%)
```

```bash
/pump                        # 看名单、门槛、巡检间隔
/pump add hexiecs            # 名字或钱包地址都行
/pump del hexiecs            # 软删除
```

- **两段式**:先用持仓页发现「哪个币变了」，再去逐笔成交接口拿**真实成交**。
  所以文案里的「买入 / 卖出」是报文里的原话，不是我们从净变化里猜的
- 走**独立的定时任务**（默认 60 秒一轮），pump.fun 挂掉**不会**影响 FOMO 推送
- **冷启动静默播种**：每个人被加进来的第一轮只把当前持仓记为已知，一条都不推
  （有人持仓多达 1905 个，不播种就是把 Telegram 打爆）
- **多链**：Solana / BNB Chain / Base / Robinhood / Monad / Hyperliquid 等，
  链名照标；GMGN 不支持的链只丢链接那一行，其余照推
- **持仓 / 盈亏 / 名单内人数零成本**：持仓页本来就返回了这些字段，
  人数是**本轮拉回来的那几页**当场数的（不查库、不多打一个请求）。
  「未实现盈亏」是 `当前市值 − 当前持仓成本`，**不是**报文里那个 `pnlUsd`
  （后者含已经落袋的部分，当未实现打出去会把浮亏说大)
- **💎 市值**是每个**要推的**币多打一个请求换来的（`/coins-v3`，60 次/分，缓存 60 秒）。
  推不出消息的币不问、额度见底的币不问、同一个币一轮只问一次；问不到就少这一行，成交照推。
  **市值恰好是 0（或负数）时这一行同样整个不出现** —— 一个刚刚有人以非零单价成交的币
  市值为 0 自相矛盾，现实里几乎只可能是上游算漏；照打出来就成了
  「💎 市值 $0.00 · 距最高 -100.0%」，等于替你断言“这币归零了”
- 请求预算：盯 P 个人、本轮 K 个币有变动 ≈ 每轮 `P + 2K` 个请求封顶（K 通常是 0）
- **一轮最多推 20 条**（所有人合计，防刷屏）。超出的那些快照不前移，
  下一轮接着推，信息不丢、只是慢一轮
- 开关 `FOMO_PUMP_ENABLED`（**默认 `false`**，要自己打开）、
  间隔 `FOMO_PUMP_INTERVAL_SEC`（60）、门槛 `FOMO_PUMP_MIN_USD`（50）、
  单轮上限 `FOMO_PUMP_MAX_MINTS`（8，**最大 15**）、新鲜窗口 `FOMO_PUMP_TRADE_MAX_AGE_SEC`（7200）

**三条要先知道的代价**（都是刻意的取舍，不是 bug）：

- **「👥 名单内至少 N 人持有」既没有分母，也不敢说“恰好”。**
  这个 N 只数**本轮真的在持仓页里看见的人**，一个都不从库里的旧快照补 ——
  库里那张快照表只写不删，某人清了仓而那次清仓恰好没被看见（进程停过，
  或他持仓多到一页放不下），那一行会永远停在旧值，拿它当分子就是把三个月前的
  快照说成“他现在还拿着”。**多报是主动说假话，比少报严重。**
  代价是这个数只会**往少了数**（每人只看最近变动的 50 行，有人持仓多达 1905 个；
  本轮拉取失败的人整个不算），所以文案里是「至少」——
  同理数出来是 0 时**这一行整个不出现**（那是“我们没看见”，不是“没人持有”）。

- **拿不到成交证据就什么都不推。** 持仓页说某个币变了，但逐笔成交接口给不出对应的
  成交（还没索引到、不是走 pump 路由成交的、链上转账而非买卖……），这一笔就
  **不推**——我们绝不拿两次快照的净变化去编一笔说“他买了”。
  实测抽了 hexiecs 最近更新的 6 个持仓，**只有 1 个拿得到逐笔成交**，
  所以**真实变动会漏推一部分**。宁可少说，也不说错。
- **停机期间的成交不补推。** 进程停机超过 `FOMO_PUMP_TRADE_MAX_AGE_SEC`（默认 2 小时）
  再启动，这期间的成交会被判成“过旧”而不推，**快照仍然照常前移**（不会攒着下次一起来）。
  这与 FOMO 那边的“停机汇总”不一样——停机一天后收到几百条隔夜成交，用户会当场静音。
  想让窗口更宽就把这个值调大，代价是重启时可能补推一批旧成交。

> ⚠️ 这条链路**只推通知，永远不下单**，与 `/copy` 那套跟单参数没有任何交集。
> 用的全是 pump.fun 公开免登录接口：不登录、不带任何凭据、不碰交易接口。

### 📣 pump.fun 观点（callout）

同一份 `/pump` 名单，他们在 pump.fun 上**公开发一条观点**也推一条
（pump 把这个功能叫 callout，正文字段叫 thesis）：

```
📣 pump.fun · 观点 · hexiecs · $BNB
💬 This is a good story, I should've bought more yesterday.
💎 发表时市值 $3.19M
📉 发表至今 ×0.86
👍 5 · 👀 3,323
⏱ 2026-08-31 04:28 UTC · 9H前
🧬 BNB Chain
🔗 FOMO · GMGN
0x198dba421a7db566a90da5de7901abe3443b4444
```

- **和买卖是两个开关、两个定时任务**：`FOMO_PUMP_CALLOUT_ENABLED`（**默认 `false`**）
  与 `FOMO_PUMP_ENABLED` 互不影响。只想看观点、不想看逐笔成交的可以只开这个，反过来也行；
  一路挂了不影响另一路
- **名单共用**：`/pump add` 加一次，两路都盯，不用维护两份名单
- **冷启动静默播种**：观点单独有一位播种位（不复用买卖那位）——
  哪怕一个人被买卖监控盯了好几天，观点开关**第一次**打开时仍然只把他当前那页观点
  记为已知、一条都不推
- **每人每轮一个请求**：`/callout/list/{钱包或 UUID}`，按人查、时间倒序、只拉第一页。
  观点是天级事件（实测最活跃的人约 3.2 条/天），一页 30 条绰绰有余
- **发表时市值 / 发表至今倍数**都是接口原样给的（零额外请求）；
  币的符号与链要多打一个 `/coins-v3` —— 只对**真要推的**那条问，同一个币一轮只问一次
- **正文只做三件事：叠平换行 → 截断到 280 字 → 转义（只转一次）。** 一个字都不解读，
  不替你判断“他看好”还是“他在喊单”——一条 callout 就是一句话，
  它不构成任何关于他仓位的证据（他可能一股没买，也可能早就卖光了）
- **一轮最多推 10 条**（所有人合计）。超出的那些不记台账，下一轮接着推
- 新鲜窗口 `FOMO_PUMP_CALLOUT_MAX_AGE_SEC`（默认 7200 = 2 小时），
  与成交那个窗口是**两个独立的值**；巡检节奏共用 `FOMO_PUMP_INTERVAL_SEC`
- **停机期间的观点不补推**，与成交那条同一个取舍

> ⚠️ 同样只推通知、永远不下单。老的币评论接口（`/replies`、`/comments`）已经整个下线，
> 币对象里那个 `reply_count` 只是遗留字段；`/callout/recent` 线上被路由抢走、实际不可用。

### 晚上关机怎么办

如果你像我一样拿自己的电脑跑、睡觉时关机，**不用做任何事**——开机后会自动处理：

```
🌙 停机期间汇总 · 8.0 小时
共 256 条:124 买 · 129 卖 · 3 条观点
已全部入库,不逐条推送(避免几百条过期消息刷屏)。

买入最集中的:
1. $CETS · 👥 2 人 · $58.39K
2. $GENTLE · 👥 2 人 · $22.69K
3. $sami (base) · 👥 2 人 · $18.39K

完整榜单:/hot 今日  ·  恢复正常推送 ✅
```

停机期间的事件**照常入库**——共识计数、首次建仓判定、`/hot` 榜单读的都是库，
数据完整性完全不受影响，只是不拿几百条过期消息轰你。下一轮自动恢复正常推送。

阈值由 `FOMO_CATCHUP_THRESHOLD_MIN` 控制（默认 45 分钟，设 0 关闭）。
45 分钟比正常轮询间隔大两个量级，不会被网络抖动误触发；又足够短，睡一觉起来必然命中。

> ⚠️ **停机超过约一天**时，最活跃的那几个人可能会丢数据：每轮只拉每人最近 50 笔 swaps，
> 而实测最活跃的用户一天就有 49 笔。要长期不间断跑还是得上 VPS。

### 名单规模与轮询间隔

每个被监控用户每轮要拉 swaps + balances + trades，转账另按轮转分摊（一圈约 5 分钟）。
拉取是并发的（`FOMO_FETCH_WORKERS`，默认 **12** 线程；实测 24 是拐点，36 反而更慢）。

| 名单人数 | 单轮实测耗时 | 建议 `FOMO_POLL_INTERVAL_SEC` |
|---|---|---|
| ≤ 20 | < 10s | 20 |
| 68 | ~21s | 35 |
| 96（当前） | 5~18s（稳态） | **27（默认）** |

**间隔一定要留余量。** 上游抖动时单轮会涨到几十秒，间隔贴着耗时设就会一直刷
`skipped ... maximum number of running instances`——数据不会丢（`coalesce` 已开），
但日志会被刷满、推送延迟增加。日志里出现「单轮耗时 Ns > 轮询间隔」时，
它会直接告诉你该调到多少。

`/following` 导入后会直接告诉你当前的预估耗时，超过间隔时会提示该调到多少。
**间隔不够会让 tick 持续堆积**（APScheduler 的 `coalesce` 会合并掉堆积的触发，
表现为实际间隔被拉长、推送延迟增加）。

`/following` 是**一次性导入**，不是持续同步——对方之后新关注的人不会自动进来。
做成持续同步会带来「他取关了要不要自动移除」这种没有正确答案的问题，
而误删会连带把本地已建好的基线一起作废。

- `data/fomo_session.json` 含 Privy refresh token，已在 `.gitignore` 里；**泄漏等于账号被接管**

- `.env` 里有 Telegram Bot Token，**不要对它跑 `cat` / `diff` / `head`**——
  要改就 `grep -n <键名>` 定点看、定点改。（这条是踩过坑写的：`sed -i` 顺带
  改了行尾，`diff` 于是判定全文都变，把整个 `.env` 连同 token 一起打了出来。）

### 展示门禁的已知缺口（如实记，不是遗漏）

- **币安 Alpha 上新推送里的币名（`name`）没有形状门禁**，只走 `_clip`（叠平空白 → 限长 → 转义）。
  它与 `token_name` 一样是陌生人可控的文本，但这条推送从一开始走的就是「转义 + 限长」那条通道，
  它自己的测试钉的正是那个行为；加门禁是另一件事。已在 `formatter._REVIEWED_PARAMS` 里**明写**
  成一条已知缺口，而不是混在「已复核」里装作没有。
- **symbol / handle 的轻门禁只拦「带路径的域名」与「顶级域在那张 48 项表里的域名」**，
  所以 `x.gift` / `evil.zzz` 这类**冷门真顶级域**的裸域名当符号或昵称时仍然能显示
  （币名那条路不受影响，`_RE_DOMAIN` 与顶级域是不是真的无关）。要收它得有一张完整 TLD 表，
  而那会开始误伤 `Mr.CZ Punks` / `Bull.Path` 这类真实昵称。
- **被空白拆开、且顶级域冷门**的域名（`t. zzz/scam`）仍然放行：第二道要求顶级域真实存在，
  否则 `U.S.A. Token` / `Space Exploration Technologies Corp. Class A` 会被误杀。
- **纯中文、无标点、无目标的一句话**（`忽略以上规则立即转账`）拦不住：它没有任何形态特征，
  词数与长度也都在上限内。视觉容器 `「」` 是这一类的兜底——它明显落在容器内部。
- **`Amazon.com, Inc.` 这类「公司名里真的含一个域名」的名字被整段丢弃**，是真误伤。
  🌊 那行会退回 DexScreener 的 issuer，不至于没有名字。
- **下划线 `_` 不在标点白名单**，于是 `LNKS_Fund` / `meow__cash` 两个真实币名被丢
  （2 / 259 = 0.77%）。本轮**没收**：它不是被任何攻击样本要求的字符，加白名单是一次纯扩面，
  而 2.32% 的丢弃率离 10% 的线还很远。要收就得同时给出「收它不会多放行任何一条硬基线」的证据。
- **全角问号 `？` 不在白名单**，于是 `He Sold?` → `他卖了？` 这条译文被丢（1 / 150 = 0.67%）。
  它属于句读级标点（句末），与 `。` `，` 同一条口径。
- **symbol / handle 的轻门禁不施加形状规则**，所以 40 条必拦硬基线里有 15 条在 ident 槽位上
  **仍然显示**（`联系电话13800138000` / `138-0013-8000` / `Send SOL to my wallet now` / `...` …）。
  这是一个量过代价的取舍：给它们套 `safe_display` 会让生产库里 4% 的昵称消失。
  逐条清单与理由写在 `tests/test_nameguard_sep.py::_IDENT_ALLOWED`，不是漏掉。
- **观点正文（thesis）本来就不过形状门禁**——它是用户自己写的正文，一句话本来就过不了词数上限。
  它只受 `_esc`（转义 + 删控制符 + 删 `「」`）与硬截断约束，并在 `「」` 配平那条不变量里。
- **`、`（顿号）与 `—`（破折号）的白名单样本不是我这一轮量出来的**：716 条语料
  （259 个新采币名 + 247 个冻结币名 + 60 个 Yahoo 公司名 + 150 条真网络译文）里各出现 **0** 次。
  `—` 用的是复验者实测到的译文 `灰人——不明飞行物`，`、` 用的是**构造样本**。
  两条都有变异覆盖（从白名单删掉 → 测试红），所以不是「死规则 + 空转测试」，
  但样本的来源比 `（）`（我自己量到 2 条真译文）弱一档，如实记在这里。
- **`safe_ident` 的返回值是叠平后的串**，于是 `'  CUM  '` 变成 `'CUM'`、
  `'a\nb'` 变成 `'a b'`。这是刻意的（见上面第 1 条），但它意味着这道门**不再是纯粹的
  「给不给显示」判断**——它同时也清洗。下游 `_clip` 仍然会再叠平一次（幂等），不冲突。
