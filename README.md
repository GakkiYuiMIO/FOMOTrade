# FOMOTrade

监控 [fomo.family](https://fomo.family) 上指定用户的**买入 / 卖出 / 观点**，实时推送到 Telegram Bot。

在同类监控的基础上多做几件事：

- 🌱 **首次建仓识别** —— 这个人是第一次碰这个币，还是在加仓
- 👥 **共识计数** —— 你的监控名单里有多少人买过这个币、还有多少人仍持有
- 📥 **筹码分发预警** —— 名单里有 3 个以上的人「**收到**」同一个币（从外部钱包转入，
  不是自己掏钱买），立刻推送。这往往是项目方在分发筹码，跟买入是相反的信号
- 🆕 **币安 Alpha 上新** —— 币安 Alpha 有新代币上架就推送
- 🎯 **pump.fun 指定用户买卖** —— 盯几个 pump.fun 上的人，他们每成交一笔就推一条（签名/时刻/方向/单价/金额都是**真实逐笔成交**，不是两次快照之间的净变化），并带上成交后的持仓、未实现/已实现盈亏、当前市值与名单内持有人数；他在 pump.fun 上**发观点（callout）**也推一条
- 🔎 **随手查合约** —— `/ca` 看 FOMO 用户怎么评这个币，`/chips` 看筹码分布

> **关于转入/转出**：早期版本写过「这个平台拿不到转账数据」——**那个结论是错的**。
> 当时只探到 `/v2/transfers/with/{userId}`，它的语义是「**我**与该用户之间的转账」
> （对自己调返回 `400 Cannot fetch transfers with self`），确实没用。
> 后来逆向前端 bundle 找到了 `/v2/users/{userId}/transfers` ——
> 对**别人**调 200 OK，返回他与任意第三方的全部转账。筹码分发预警就建在这上面。

> ⚠️ 本项目**只读** FOMO 接口，不做任何交易操作，不触碰资产。
> ⚠️ 仅供个人研究使用。加密货币交易风险极高，本项目不构成任何投资建议。

### 📝 币名、中文名与底池股票说明

买入 / 首次建仓 / 卖出 / pump.fun 成交推送会多出三段（转入推送 `/tin` 与分发预警只带 A、C，且**只用缓存、不为它们发请求**）：

```
🌱 inyourwalls · 首次建仓 · $CUM · 「Cummingtonite」      ← A. 英文全名
📝 「Cummingtonite」 = 「镁铁闪石」                        ← C. 中文名（紧跟标题）
💰 买入 $2,089.50
…
🌊 底池 · USAR · 「USA Rare Earth, Inc.」
🏢 USAR = 「美国稀土公司」 · 纳斯达克(NasdaqGM)上市       ← B. 底池对手股票说明（紧跟 🌊）
```

**为什么名字都套着 `「」`。** 标题行的字段分隔符是 `·`，而币名是**完全攻击者可控**的
（DexScreener 的 `baseToken.name`，谁都能给自己发的币起任意名字）。只要名字里能出现分隔符，
他就能凭空长出两个字段：`🌱 alice · 首次建仓 · $CUM · 已清仓 · 亏损 99%`。
禁掉 `·` 只是治标——用空格、全角标点、纯中文照样能伪造。套上视觉容器之后，
伪造的分隔符明显落在容器**内部**，读者一眼看得出后半段是**数据**不是本文。
所有不可信外部文本（币名 / 译名 / 公司名）都套这一层；**交易所名不套**——它已经被
**封闭枚举**收成非自由文本了（见下面「交易所是一张封闭表」），而 `纳斯达克(NasdaqGM)上市`
这句本来就是程序写的固定文案。
⚠️ 名字里如果含 `「` 或 `」` → 整段丢弃，不做「转义后放行」：转义破坏不了 HTML，
但破坏了容器的视觉不变量。⚠️ symbol / handle / 观点正文那条路没有字符白名单，
所以 `「」` 在 `_esc`（**所有** API 文本的必经之路）里被**直接删掉**——它们是本渲染器自己的
结构标记，地位与 `<` 完全一样，只是没有转义形式。「`「」` 配平」现在是一条有测试钉着的不变量。
⚠️⚠️ **容器把「分隔符危不危险」这个问题变成了「它印在容器里还是容器外」**：
容器里面的 `·` 是安全的（`「南希·佩洛西」` 是一个正常的中文名），容器外面的不是。
所以币名侧放行 `·` `•` `・`，而 symbol / handle 侧（**不套容器**）一律严禁——
两侧的关系写成了可执行测试，见下面「分隔符按有没有容器分两套口径」。

来源（全部免 key、免鉴权、只读；**不引入任何新依赖**）：

- **A** 来自 DexScreener —— 底池那一行本来就在打的同一份响应里，`baseToken.name` 就是币全名，四条链都取，**不另发请求**。
- **C** 两级翻译：先查**维基百科跨语言链接**（正式中文名，繁体自动转简体：Cummingtonite → 鎂鐵閃石 → 镁铁闪石；消歧义页当作没有），
  没有条目再走 **Google 翻译的免费通道**（`translate.googleapis.com`，**非官方接口**，随时可能失效——失效时这一行消失、其余照常。
  它也会翻错：Cummingtonite 会被译成「铜明石」，这就是维基必须优先的理由）。
- **B** 的事实（公司全名、交易所代码）**只从 Yahoo Finance** 来（免 key 的 `v8/finance/chart` 接口），中文公司名走与 C 相同的两级
  （维基用剥掉 Inc./Corp. 后缀的名字查：NVIDIA Corporation → NVIDIA → 英伟达）。交易所是一张**封闭表**（见下），
  中文只做静态映射（Nasdaq\* → 纳斯达克、NYSE → 纽约证券交易所、NYSEArca → 纽交所 Arca、NYSE American/AMEX → 美国证券交易所），映射不到的只印原代码。

**交易所是一张封闭表，不是模式匹配。** 这个字段曾经用正则 `[A-Za-z][A-Za-z0-9 .\-]{0,19}` 收，
而那个字符集里有 `.` 和 `-`——**所有 ≤20 字符的裸域名整段匹配**：`t.me` / `discord.gg` /
`www.evil-airdrop.com` / `bit.ly` / `vitalik.eth` 全部放行，而它是渲染收口表里**唯一**不走
形状白名单的字段、还进永久缓存。交易所本来就是有限集合，改成显式枚举之后 `t.me` 不是「被拦住」，
而是**根本不在允许集合里**。表是 2026-09-02 实测出来的：87 个真实 ticker 去 Yahoo

那些公司恰恰是没有在交易所上市的——印成「OTC Markets OTCPK 上市」是一句事实错误的话。
现在印 `OTC Markets OTCPK 场外交易`。
⚠️⚠️ **同一家交易所的每一种写法必须印成同一个中文**（本轮修）。上一版收了 `NYSE American` 与
`AMEX` 却漏了无空格写法 `NYSEAmerican`，于是同一家交易所一会儿是「美国证券交易所」、
一会儿是光秃秃的 `NYSEAmerican`；`Cboe US` / `BATS`（同一家的新旧名）也各印各的。
现在 14 个别名在展示映射里各有一行，并有一条测试逐组断言「中文那一段相同」。
- 🌊 那行的**对手全名**优先用 Yahoo 的 `longName`（`USA Rare Earth, Inc.`），Yahoo 拿不到才退回 DexScreener 剥完判据后缀的
  名字（`USA Rare Earth`）——Yahoo 是更权威的来源，`, Inc.` 这一截只有它有。

哪些情况**整段不出现**（缺了就少一段，绝不打 N/A）：

- A：DexScreener 没这个币；名字与 symbol 相同（忽略大小写与 `$`）。
- C：名字缺失 / 与 symbol 相同 / 本身含中日韩文字 / 纯数字纯符号 / 短于 2 字符
  （长度上限就是展示门禁的 40 字符，namecn 里那个 64 是死常量，已删）；
  译文与原文相同、或与送去查维基的那个词相同（SpaceX → SpaceX）；译文长度超过原文 4 倍；
  译文里出现原文中没有的英文单词（4 位以上）。
  ⚠️ **音译人名的间隔号本轮起放行。** 中文音译习惯用间隔号 `·`（`Nikita Bier` → `尼基塔·比尔`），
  上一版把它当字段分隔符整段丢弃，实测 150 条真网络译文里因此丢掉 5 条
  （`南希·佩洛西` / `尼基塔·比尔` / `凯莉·克劳德` / `古奇·莫蒂` / `利尔·芬德盖伊`）——那是纯粹的误杀：
  译文印在 📝 行的 `「」` **容器里面**，伪造出来的分隔符被容器困住，读者一眼看得出那是一段数据。
  换来的约束在**另一侧**：symbol / handle 不套容器，那边对分隔符**一律严禁**（见下面「轻门禁」）。
  ⚠️ 名字侧仍留一条：**含中日韩文字时分隔符两侧不许有空格**——中文排版里音译人名的间隔号
  紧贴两侧（`南希·佩洛西`），而 `已清仓 · 亏损 99%` 带空格，那是在**模仿推送自己的 SEP**。
  真网络实测（2026-09-03，150 条译文，维基优先 / Google 兜底）：**丢 1 条 = 0.67%**
  （`He Sold?` → `他卖了？`，全角问号是句末标点、不在白名单）。同一批样本在上一版是 7 条 = 4.67%。
  ⚠️ 「含中日韩文字时不许夹 5 位以上 ASCII 串」那条**继承了「凭空多出原文没有的英文串」的语义**：
  ASCII 串原样出现在原文里就不算凭空多出。少了这一句，`Tesla xStock` → `特斯拉 xStock`、
  `Exxon Mobil xStock` → `埃克森美孚 xStock` 这类正常译文会被全毙掉（xStock 全家族 100% 丢译名）。
- A / C / B 的名字段还都要过一道**展示门禁**（`src/nameguard.py`，攻击者能给自己发的币起任意名字，
  译文又走代理、可被篡改，所以两边都当成敌意输入）。它拦的不只是字符，更是**形状**——
  `Send SOL to my wallet now` 每个字符都在白名单里，但它是 6 个词的一句话，不是名字。六步：
  1. 含 **bidi 控制符**（RTL 覆盖 U+202E 那一类）→ **整段丢弃**。这类字符唯一的用途是让显示顺序
     不等于字符顺序（`币<U+202E> pmup` 读者看到的是 `币 pump`），删掉之后剩下的是作者从没写过的名字。
  2. 删掉其余 Unicode 格式控制符（零宽空格 U+200B——`t.<U+200B>me` 这种拆开写的绕过就是这一步还原的），
     并把所有空白替身（NBSP、表意空格…）叠平。
  3. 形态：`scheme:`（含 `javascript:` / `data:` 这种**单冒号**的）/ 域名（`t.me`、`evil.com`、`vitalik.eth`、
     `evil.zzz`——与顶级域是不是真的无关；`Inc.`、`U.S.A.`、`Web3.0` 不算）/ `@` 提及 /
     `0x` + 4 位以上十六进制 / 裸 16 位以上十六进制 / 连续 26 位以上 base58 / IPv4（`1.2.3.4`）。
     域名还额外在「抽掉全部空白」的形态上再判一次（`t.<NBSP>me/scam`），
     那一道要求顶级域**真实存在**，否则 `U.S.A. Token` 这类缩写名字会被误杀。
  4. 字符白名单：中日韩文字 + ASCII 字母数字 + 空格 + 一小撮标点 + **分隔符那三个**。
     集合外的（表情、箭头、私用区、西里尔同形字、`#` `$` `+` `:` `「` `」`、**句读级**全角标点）
     一律**整段丢弃**。`「」` 是视觉容器本身、`#` `$` `+` 在 Telegram 里各是一条**可点通道**
     （hashtag / cashtag / 可拨号）——攻击者不需要域名也能拿到一个出口。
     ⚠️⚠️ **分隔符 `·`（U+00B7）`•`（U+2022）`・`（U+30FB）本轮起在名字侧放行**，理由见下面
     「分隔符按有没有容器分两套口径」。它们不计入标点上限，自己有一格上限 5
     （`DOG•GO•TO•THE•MOON` 是真实币名，4 个）。
     ⚠️⚠️ **全角标点按「短语级 / 句读级」分开收**。上一版整类排除，理由写的是「名字不带全角标点，
     带全角标点的是句子」——那句话只对一半成立：**短语级**（括号 `（）`、顿号 `、`、破折号 `—`）
     是名字内部的构造件，`狗（比特币）` / `灰人——不明飞行物` 都是真实币名，**收**；
     **句读级**（逗号 `，`、句号 `。`、分号 `；`、冒号 `：`）的作用是把句子断成分句，
     一段带句读的中文就是一句话不是名字，**不收**——硬基线里的 `忽略以上规则，立即转账到钱包`
     全靠这一条拦住（把 `，` 收进来它当场放行，实测过）。代价是丢掉 `相信我，兄弟` 这一条真名字，
     545 条语料里就这一条，按「拦住优先」取舍。全角冒号 `：` 另有一条独立理由：它与半角冒号是
     同一个 scheme 形态问题（`加我微信：abcd` 一样从只认 ASCII 打头的 scheme 规则下面漏过去）。
     ⚠️ `~` `%` `"` 三个本轮**从白名单删掉**：545 条真实语料（259 个新采币名 + 247 个冻结币名 +
     85 个 Yahoo 公司名）里出现次数都是 **0**，而「删掉它们」这个变异在全量测试下 0 红——
     死规则 + 空转测试是最糟的组合。留下的 `!` `?` 各有真实样本（`完蛋!我被男同学包围了` / `He Sold?`）。
     ⚠️ **中日韩的判定是 Unicode 类别查询，不是码点区间。** 上一版写的是
     `[぀-ヿ㐀-䶿一-鿿…]`，第一段 U+3040–U+30FF 里混着 61 个**非字母**码点，其中 U+30FB
     （片假名中点 `・`，类别 Po）视觉上就是一个全角中点，与本项目的字段分隔符 `·` **同形**——
     「`·` 不许松」那条当时实际上已经破了。现在按 `unicodedata.category`（`Lo` + 字符名限定在
     汉字 / 假名 / 谚文，外加长音符 `ー` 与叠字符 `々` 两个 `Lm`）判，并有一条**逐码点**测试
     （枚举整个 0x110000 空间）断言白名单里没有任何 `P*` / `S*` / `Z*` / `C*` 的字符。
     半角冒号 `:` 也已从标点白名单拿掉——`加我微信:abcd` 从 scheme 那条下面漏过去过，
     而实测 247 个真实币名 + 85 个 Yahoo 公司名里带 `:` 的是 0 个。
  5. **形状白名单**：长度 1–40 字符、≤5 个词、≤3 个标点、**数字总量 ≤5 个**、至少含一个字母
     或数字或汉字（纯标点的「名字」不是名字）、含中日韩文字时不许夹**原文里没有**的
     5 位以上 ASCII 字母串。
     ⚠️ 数字那条判的是**总量**不是「连续几位」。上一版写的是「连续 ≥6 位」，而 `-` `.` 空格
     都在字符白名单里——`138-0013-8000` / `138 0013 8000` / `138.0013.8000` 全部平凡绕过，
     渲染出来就是 `🌱 maxpain · 首次建仓 · $CUM · 「138-0013-8000」`。「连续 N 位」这种规则
     必然被分隔符绕开。总量规则严格强于它（连续 n 位 ⇒ 总量至少 n），所以老那条已删。
     ⚠️⚠️ 本轮又把「数字」的定义从 ASCII 扩到**数值字符**：`str.isdigit()`（覆盖 ASCII 与全角）
     加上**有数值的汉字**（一二三…十百千万）。少了后半句，`一三八零零一三八零零零` 这种
     中文数字写的手机号每个字都过得了 CJK 白名单，原样进标题。实测代价 0：545 条真实语料里
     含数值汉字最多的一条是 `八重`（1 个），离上限 5 很远。
     ⚠️ 词数数的是**有内容的**词（至少含一个字母 / 数字 / 汉字），孤立的分隔符不算一个词——
     `Circle Internet Group • Robinhood Token` 是 5 词不是 6 词，而它是一个真币股的上游原名。
     ⚠️ 词数上限 5 的依据是 **Yahoo 实测返回值** `United States Oil Fund, LP`（USO，2026-09-03 复查）。
     上一版拿 `SPDR S&P 500 ETF Trust` 当依据是错的：SPY 的 `longName` 实测是

  `HJ8688878987581`，见下面「刻意的取舍」）。

  1. **叠平**。上一版通过时返回**原串**，理由是「清洗与限长是下游 `_clip` 的职责」。那句话对
     `render_pump_trade` / `render_transfer_in_signal` / `render_alpha_listing` 成立，对

  2. **分隔符与容器字符一律严禁**，见下。

  **分隔符按「有没有容器」分两套口径**（本轮最重要的一条）。上一轮出过一个
  **两个测试文件互相矛盾**的洞：`safe_display('已清仓 · 亏损 99%')` 是 `None`（必拦基线第 1 条），
  而 `safe_ident` 对同一个串被断言**必须放行**——两边都是绿的，因为没有任何一条测试同时看着两侧。
  根因是「分隔符」这一类被漏在两套规则之外，而 **ident 恰恰是唯一不套 `「」` 容器的槽位**：
  最需要拦分隔符的地方反而最松。真正的判据不是「这个字符危不危险」，是**它印在容器里还是容器外**：

  - 币名 / 译名 / 公司名一律印在 `「」` **里面** → 伪造的分隔符被容器困住 → `·` `•` `・` **放行**。
    顺带修好一大批真误杀：`Costco • Robinhood Token`、`DOG•GO•TO•THE•MOON`、`南希·佩洛西`。
  - symbol / handle / 昵称 **不套容器**，与推送自己的 `SEP`（`' · '`）平级 → **一律严禁**。
    判据是 **Unicode 字符名查询**（`is_separator_char`，命中 **320** 个码点），不是手写码点表——
    手写表必然漏同形字（U+30FB `・` / U+FF5C `｜` / U+0387 `·` / U+2219 `∙` / U+2502 `│` …）。
    ⚠️⚠️ **本轮（G1）把类别闸门删了。** 上一版第一行是 `category(ch)[0] not in "PS" → False`，
    注释写「字母天然排除」——那句话是**错的**：Unicode 把一批视觉上就是中点 / 竖线的字符
    放在**字母类**里，它们从闸门下面整批漏过去（实测 `safe_ident('AB{x}CD')` 原样放行）：
    U+A78F `ꞏ` LATIN LETTER SINOLOGICAL DOT（字面就是中文间隔号）、U+1427 `ᐧ`、U+18DF `ᣟ`、
    U+01C0 `ǀ` / U+01C1 `ǁ`（CLICK 字母，与 `|` `‖` 同形）、U+02C8 `ˈ`。
    marker 表同时补齐了 `TWO DOT LEADER` / `RAISED DOT` / `RING POINT` / `SPOT` /
    `WORD DIVIDER` / `WORD SEPARATOR` / `TRICOLON` / `DOT PUNCTUATION` /
    `MODIFIER LETTER COLON` / `DOUBLE HYPHEN` / `SINOLOGICAL DOT` / `CLICK` /
    `HALFWIDTH IDEOGRAPHIC FULL STOP` 十三族。命中数 249 → 320，**旧命中一个没丢**。
    ⚠️ 删闸门之后唯一需要补的是一条**反向**规则：**字母**的名字里出现 `X WITH Y` 时那是
    「带修饰的字母本身」而不是那个修饰（`Ŀ`/`ŀ` = L 加一点、`Ҝ`/`ҹ` = К 加一竖、
    阿拉伯与粟特字母的 `WITH TWO DOTS VERTICALLY` / `WITH VERTICAL TAIL`），收进来是纯误伤。
    这条**只对字母生效**：对符号也排除会收窄 50 个旧命中（`⍿` VERTICAL LINE WITH MIDDLE DOT、
    `⸠` LEFT VERTICAL BAR WITH QUILL 都是货真价实的竖线同形字），那是往回开洞。
    ⚠️ `IDEOGRAPHIC FULL STOP` 这个 marker **只收半角的 U+FF61 `｡`**：半角句点是个小圆点、
    与 `·` 同形；全角的 `。` 是个明显的大圈，读者不会把它读成字段分隔，它被
    `_MUST_NOT_BE_SEPARATOR` 明确钉成「不是分隔符」。
    ⚠️⚠️ **枚举依据本轮（G2）从被测函数移到了测试这一侧。** 上一版
    `_all_separators()` 调的正是被测的 `is_separator_char`——函数收窄、枚举同步收窄、
    `leaked == []` 平凡成立：把它收窄成「只认手写的 17 个码点」，全量 3115 条 **0 红**（实测过），
    而它实际命中 249 个码点、其中 232 个没有任何直接断言。现在测试**手抄**一份判据自己遍历
    0x110000（`_enumerate_separators`），另有一条 `test_测试自己的枚举与被测函数逐码点一致`
    把两份判据钉死；`_MUST_BE_SEPARATOR` 也从 17 条扩到 **69 条**，覆盖
    Ll/Lm/Lo/Mn/Pc/Pd/Pe/Pf/Pi/Po/Ps/Sk/Sm/So 十四个类别，逐条断言 `safe_ident` 拦住它。
  - ⇒ 就分隔符这一类而言，**ident 的规则集是名字规则集的严格超集**。这条关系写成了
    **可执行测试**（`tests/test_nameguard_sep.py`：遍历整个 0x110000 空间，断言每一个分隔符类字符

- B：底池对手不是币股（🌊 行本身不出现）；Yahoo 查无；`instrumentType` 不是 EQUITY / ETF。
  公司名翻不出时仍显示交易所（`🏢 USAR · 纳斯达克(NasdaqGM)上市`）。
- ⚠️ **公司名走 Google 直译，可能造出一个并不存在的「官方中文名」。** 维基有条目的走维基
  （`NVIDIA Corporation` → `英伟达`，那是真的官方译名）；维基没条目的落到 Google，
  于是 `WhiteFiber, Inc.` 会被译成「怀特纤维公司」——这家公司**没有**这个中文名，是逐字直译拼出来的。
  仍然保留，理由是用户要的是「一眼看懂对手是哪家公司」，而不是一份官方译名表：
  「怀特纤维公司」比一个光秃秃的 `WYFI` 有用得多。译名也不是孤零零出现的——
  紧挨着的 🌊 行印的是英文原名（`🌊 底池 · WYFI · 「WhiteFiber, Inc.」`），
  🏢 行才是译名（`🏢 WYFI = 「怀特纤维公司」`），两行连着读，读者不会被译名单独带偏。

结果缓存在 `name_glossary` 表：成功**永久**（名字不会变），两级都查不到 30 天，网络失败 / Yahoo 非 2xx / 响应结构解析不出 1 小时
（只有 Yahoo 明确回 `Not Found` 才算「查无」按 30 天缓存——一次限流不该把一个代码按住一个月）。
成功行永久不过期，所以每次写入顺手裁一次：先删过期行，还超 **20000 行**就按最后更新时间最旧的先删。

**每 tick 的外呼预算**（三本账分开记，互不侵占；缓存命中不计）：

| 账 | 次数 | 空缓存时一轮能补几个 |
| --- | --- | --- |
| 币名翻译 | 8 | **4 个全新币名**（维基查无再走 Google 算 **2 次**；全都在维基查得到则 8 个） |
| 公司名翻译 | 4 | **2 个全新公司名**（同样，查无再走 Google 算 2 次） |
| Yahoo 事实 | 5 | 5 个新代码 |

再加一道**墙钟**闸门：本 tick 花在名字补全上的累计耗时超过 **20 秒**就停（`time.monotonic`）。
两道闸门任一触发即停——真正要防的风险是「外部接口把 tick 拖慢」，调用次数只是它的代理指标
（单请求超时 8 秒，光靠次数挡不住）。被闸门挡下的名字**不写任何缓存**（下一 tick 重来）但记一条 DEBUG 日志，
看这条日志出现的频率就知道容量够不够。
这些外呼的任何失败都不影响推送本身。渲染前一律 `html.escape`。`/ca` 与 `/chips` 的输出不变。

#### 🔗 社媒：URL 是本项目第一个进 `<a href>` 的外部字符串

前面所有门禁守的都是「印出来的字」，这一道守的是「点下去会去哪儿」——失败后果完全不是一个量级：
前者最坏是读者读到一句假话，后者是读者**被带到攻击者的站点**，而链接文字还是我们自己写的「网站」「Twitter」，
天然带着我们的背书。所以 `nameguard.safe_url` 的做法是**先把 URL 拆开、再对每一段做封闭判定**，
任何一步不认识就整条丢弃（绝不「清洗一下再放行」——清洗过的 URL 仍然是攻击者选的目标）：

1. **字符集**：只许 ASCII 可打印（0x21–0x7E），且 `"` `'` `<` `>` `\` `` ` `` 一律不许
   → 空白 / 控制符 / 零宽 / 非 ASCII（IDN 同形字）全部死在这一步；`"` 与 `<` 来了就整条丢弃，不靠转义兜底。
2. **长度** ≤ 200。
3. **scheme 必须逐字是 `https://`** → `javascript:` / `data:` / `tg:` / `http:` / 协议相对 `//evil.com` 全死在这一步。
4. **netloc 出现 `@`（userinfo）/ `:`（端口）/ `[` `]`（IPv6）→ 整条丢弃** → `https://x.com@evil.com` 死在这一步。
5. **host 逐段 LDH 校验**（小写字母数字与 `-`、不许首尾 `-`、每段 ≤63、2~6 段、不许 `xn--`），
   **顶级域必须是纯 ASCII 字母且 ≥2 位** → 纯数字 IP、`x.com.` 尾点、西里尔域名全死在这一步。
   ⚠️ 这里**没有**顶级域白名单（上一版有，实测误杀 8.16% 的真实官网，见下）。
6. **社媒各类的 host 必须逐字等于封闭表里的某一项**（`x.com` / `twitter.com` / `t.me` / `telegram.me` /
   `discord.gg` / `discord.com` / `discordapp.com` / `reddit.com` / `github.com` 及其 `www.` 变体）——
   **等值比对，不是后缀比对** → `https://x.com.evil.com` 死在这一步。短链（`bit.ly` 之类）**一律不收**：
   短链的目标不可见，收它等于把整张表作废。

**「网站」那一类为什么放开 host（取舍与代价）。** 它的 host 本质上不可枚举——每个项目一个域名，
这正是「项目自己的站」的定义。三个选项：(a) 整条不显示，等于没做这件事；(b) 只显示文字不给链接，
但 URL 本身是攻击者可控的自由文本，当文字印出去反而更糟；(c) 放开 host，但把**其余五道**全部收死。
选 (c)。**代价明写：一个能发币的人可以让这个链接指向他选的任意 https 站点。**
缓解只有三条，都不消除风险：链接文字永远是我们自己的常量（URL 本身不出现在消息里）；
scheme 只许 https 再加整套形态校验；同一条信息在 fomo.family 的代币页上本来就以同样的形式对同一批读者展示，
我们没有新增一个上游没有的通道。

##### ⚠️⚠️ 顶级域白名单为什么被去掉了，以及「官网」为什么改叫「网站」

上一版还压了一张顶级域白名单。实测证明它**既拦不住坏人、又误杀好人**——
抽 1600 个「生产库里被推送过」的代币走 DexScreener（0 失败），拿到 **662 条官网 / 496 个去重域名**：

| | 丢弃条目 | 丢弃率 |
| --- | ---: | ---: |
| 旧版（有顶级域白名单） | 54 / 662 | **8.16%** |
| 现在（只判形态） | 12 / 662 | **1.81%** |

差额的 **42 条是纯粹被那张白名单误杀的**，涉及 **29 个不同的顶级域**，而且丢的根本不是 exotic TLD：
`www.whitehouse.gov` · `youtu.be`(4) · `linktr.ee`(3) · `giwa.markets`(4) · `slate.foundation` ·
`archive.ph` · `stonk.rocks` · `burger.mom` · `striker.cat` · `wojak.bid` · `unicorn.place` ·
`pons.company` · `agentos.services` · `nov.ag` · `hoodmorn.ing` …
靠往表里补是补不完的（TLD 有一千多个且还在增加）。
反过来，那张表里**本来就有** `xyz` / `top` / `vip` / `cc` / `ws` / `gd` / `ly` ——
一次性域名与短链域全在白名单内，它对「发币人指向自己选的站」**基本不构成约束**。
⇒ 去掉表，只留「顶级域必须是纯 ASCII 字母且 ≥2 位」这一条**形态**判据
（它挡的是 `1.2.3.4` 这种 IP 字面量和 `x.com.` 这种尾点——那才是这一道真正在干的活）。
剩下被丢的 12 条：10 条是 `http://` 明文（**刻意不放行**）、1 条 URL 自带空格、1 条超过 200 字符。

**与之配套：链接文字从「官网」改成「网站」。** 「官网」是**我们替上游作证**「这是官方的」，
而这条 URL 指向哪儿完全由发币人决定（这一类刻意放开了 host）。实测样本里就有指向娱乐新闻、
指向某条推文的所谓「官网」。放开 host 的同时还说它是「官方」，等于把风险原样放大；
「网站」只陈述一件我们确实知道的事——**这里有一个网站链接**。
（同一条口径也解释了为什么不显示域名本身：域名是上游可控的自由文本，显示它等于又开一个文字通道。）

**仍然保留的已知代价**：`http://` 一律不放行（本次样本里 10 条，1.51%）；URL 超过 200 字符整条丢
（样本里 3 条，全是带 `utm_*` 追踪参数的分享链接）——那道长度闸是「超长 URL → notifier 盲切 →
HTML 不配平 → Telegram 400 整条推送发不出去」这条链路上的唯一一道，不放宽。

其它三条规矩：

- **链接文字永远是我们自己的常量**（网站 / Twitter / Telegram / Discord / Reddit / GitHub），
  **永远不用上游给的 `websites[].label`**——那是发币的人填的自由文本，而链接文字带着我们的背书
  （让他写「官方客服」再指向自己的站，是这一整块最贵的那个洞）。
- **同类只取第一个**（有的币把同一个 type 填了好几条），显示顺序**固定**（不随上游数组顺序漂移，
  否则同一个币两次推送里链接顺序不一样，会让人以为数据变了）。
- **未知的 type 一律跳过**，不显示原文——「显示原文」等于把上游的自由文本当链接文字印出去。
- **社媒只取「我们问的那个币是 `baseToken`」的那条 pair 的 `info`**。`pair.info` 描述的是这条 pair 的基础币，
  而 base/quote 的方向不固定（实测 $AI 在 `AI/NVDA` 里是 base、在 `CLANKER/AI` 这类池里是 quote）——
  在我方是 quote 的 pair 上照抄 `info`，印出去的就是**另一个币的网站和推特**：一条读起来完全正常、错得毫无痕迹的假信息。

#### 哪些情况这三行不出现

- **🚀 发射台**：上游没有 `launchpadName`（solana 9.5% / robinhood 29.6% / bsc 23.2% / base 43.5% /
  monad 31.2% / ethereum 96.2% 的币本来就没有）；名字不在封闭表里（此时打一条 WARNING）；
  本 tick 挨了限速闸或 429。
- **🧑‍🤝‍🧑 持有人**：上游给 `0`（哨兵）；两个源都拿不到；数值 ≤0 或 >10 亿；本 tick 挨了限速闸或 429；
  **以及转入推送这条路径——见下。**
- **🔗 社媒**：项目方发币时没填（用户原话：「网站 推特 这种 是发币的时候项目方填的，可能有 也可能没」）；
  DexScreener 没这个币；我方只在 quote 侧出现；填了但每一条都过不了门禁
  （实测整体 5.05%，其中一半是 `tiktok` / `instagram` / `farcaster` 这些**未收录的类别**）。

##### ⚠️ 转入推送为什么没有 🧑‍🤝‍🧑 那一行（H6，如实登记）

转入推送（`/tin`、转入聚合）与分发预警走的是「**只读缓存、绝不发请求**」那条路。
而两份缓存的寿命完全不同：

- **发射台**落在 `name_glossary` 里、成功是**永久**的 ⇒ 转入推送**有** 🚀；
- **持有人**只有 **90 秒的进程内存**缓存 ⇒ 一条转入几乎不可能正好落在这 90 秒里，
  于是转入推送**实际上几乎永远没有** 🧑‍🤝‍🧑。

给 holders 也落 SQLite 的方案**考虑过、否掉了**：短 TTL（90 秒）落库，转入那条路照样命中不了，
只是多了磁盘写；长 TTL（小时级）落库，就是在一条刚刚发生的转账旁边印一个几小时前的持有人数——
持有人数是快变量，**印一个陈旧的数字就是印一句假话**（§10.3：错的比没有更糟）。
所以保持现状，并把这件事写在这里，而不是做成「看起来有、其实是旧的」那种半吊子。

#### 限速与缓存

`filterTokens` 的限速实测很紧：**无间隔连打第 10 次就触发 Cloudflare 429**，`retry-after` = 203 秒
（封禁期继续打不会延长）。所以：

- 一个 tick 把待推代币**攒成一个批次、跨链混批、一次请求**（>200 个才切第二批，一轮最多两批）；
- **任意两次请求间隔 ≥ 10 秒，绝不并发**。这把闸是**进程级**的——poller 与 pump.fun watcher 各持一个
  lookup 实例，做成实例级等于把 10 秒间隔悄悄变成 5 秒，而限流是按 IP 算的；
- 等闸最多等 **2 秒**（这个等待直接加在 tick 的墙钟上），等不到就这一轮不查、那两行消失，**绝不阻塞推送**；
- 429 → 读 `retry-after` 进冷却，本 tick 这两行整体消失，**不重试**。

验证(2026-09-03 真网络):走生产的限速闸连打 **14 次 / 每次间隔 10 秒 → 0 个 429**(总墙钟 130.5 秒);
全量枚举那一轮又打了 **22 批 / 同样间隔 → 0 个 429**。本轮全程没有触发过任何一次 429。

Blockscout 未观察到限速（调研阶段 6 并发 1680 次请求 0 个 429），但仍设每轮次数上限
（持有人 12 次 / Pons 版本判定 2 次）+ 墙钟闸门（8 秒）——真正要防的是「外部接口把 tick 拖慢」
（本项目有过 tick 从 5s 拖到 90s 的教训），而 Blockscout 实测每个请求约 860ms。

缓存（复用 `name_glossary` 表，三档 TTL 各自独立）：

| 内容 | 成功 | 查无 | 失败 |
| --- | --- | --- | --- |
| 发射台名 | **永久**（发射台是代币出生时定死的属性） | 7 天 | 1 小时 |
| Pons V1/V2 判定 | **永久** | 7 天 | 1 小时 |
| 持有人数 | **内存 90 秒**（刻意不落库，代价见上面 H6 那段） | 同左 | 不缓存 |
| 社媒 | 随底池那份 **6 小时内存缓存**一起走（零新增请求，不另开缓存） | — | — |

⚠️ 失败与查无的 TTL **必须分开**：把「一次网络抖动」按住 7 天，等于让一行消失一周，
而且没有任何日志会说是缓存干的。

发射台永久缓存的收益是实测得到的:第二轮只查 robinhood 的 25 个币时,**filterTokens 请求数 = 0**
(发射台在库里、而 robinhood 的持有人走 Blockscout)——`filterTokens` 正是限速最紧的那个端点。

**这些外呼的任何失败都不影响推送本身。** `/ca` 与 `/chips` 的输出不变。

| --- | --- | --- | --- |
| `userHandle` | 丢 **0/150 = 0.00%** | 丢 14/150 = 9.33% | 丢 0/150（但**允许空格**） |
| `displayName` | 丢 **32/150 = 21.33%** | 丢 13/150 = 8.67% | 丢 1/150 |

这一行长得像**一条记录**（`#28 「名字」 · 持仓 · 粉丝 · 盈亏`），混进一句话就是一条**伪造的记录**——
所以门必须是封闭形状（`safe_ident` 允许空格，`Send SOL to my wallet now` 整句能穿过去）。
而封闭形状放在 `displayName` 上要丢 21.33%（中文名 / 空格 / emoji），

handle 才是能拿去 FOMO 上搜到人的那个标识。
⚠️ 也**不写成 `@handle`**：Telegram 会把 `@xxx` 渲染成可点的用户名提及，等于替一个陌生账号做链接。
⚠️ handle 过不了门禁 → 退回「未知用户」而**不是**整行消失：这一行的其余三段是真值，
`#N` 本身就能在榜上定位到人；丢掉整行反而会让上面那句「N 人」与列出的行数对不上。
⚠️ 持有人的留言（`comment`）**不显示**：一行已经够长，而它是完全自由的正文。

**每一个**槽位（含三者同时投毒），零泄漏。

#### 请求预算（这是推送路径，比 `/chips` 严得多）

- **榜单是全局的**（与币无关）→ **进程级**缓存，一次拉 150 行给所有推送共用。
  TTL **300 秒**：24h 榜是一个 24 小时滚动窗口，前 150 名的集合是十分钟量级才换人；
  而推送侧 15~27 秒一个 tick，5 分钟 TTL 把榜单请求压到 ≤12 次/小时。
  失败另记一个更短的负缓存（**60 秒**），免得一次抖动把这一块按住整整 5 分钟。
  ⚠️ 缓存做成**进程级单例**（与 `tokeninfo._GATE` 同一条理由）：poller 与 pump.fun watcher
  各持一个 lookup 实例，实例级缓存等于把这个全局请求打两遍。
- **持有人是按币的** → 每条推送 1 个请求，并且有**每 tick 次数上限 6** + **每 tick 墙钟闸 6 秒**
  （榜单那次也算进墙钟，而且**拉榜那一次在发出去之前**就要过这道闸）。
  任一触发 → 后面的币这一块不显示，**绝不阻塞推送**。
- 持有人响应另有一份 **90 秒内存缓存**，只给下面那条只读路径兜底。

#### ⚠️⚠️ 「绝不阻塞推送」是怎么做到的（这一段是被实测打脸之后重做的）

这一块是同步跑在**发消息之前**的（`poller._board_holder_map` 在 `_dispatch` 里）。
上一版它复用主路径那套重试机（3 次尝试 / 12 秒超时 / 429 按服务端 `Retry-After` 退避、夹在 60s），
离线量化（把 `sleep` 换成只记账）出来的最坏值是：

| 场景 | 请求次数 | sleep | 叠上超时后的**单个请求**阻塞 |
| --- | --- | --- | --- |
| `429` + `Retry-After: 60` | 3 | `62.49 + 41.78 = 104.27s` | **140.3 秒** |
| `503` | 3 | `1.53 + 3.48 = 5.01s` | 41.0 秒 |

**一行装饰能把整个 tick 的推送卡住两分多钟。** 现在换成三条：

1. **自己一条请求策略**（`client._fetch_ok(..., fast_fail=True)`）：
   **单次尝试、5 秒超时、不按 `Retry-After` 睡、不退避重试**。
   ⚠️ 这条**绝不影响主路径** —— `fast_fail` 默认 `False`，为 `False` 时走的是与上一版
   逐字节相同的代码路径（`self._request(path, params)`，一个多余的关键字都不带），
   有一条用**签名里根本没有 `timeout` 形参**的假实现写的用例逐条钉住。
2. **拉榜那一次也在发之前过墙钟闸**。上一版只在事后记账 —— 闸只挡「下一个请求」，
   而拉榜那一次**根本不在闸的管辖内**。
3. **榜单那把闸是 `acquire(blocking=False)`**：拿不到就说明别的 job 正在拉，
   本轮这一块直接不显示。⚠️ 拿不到闸 **≠ 失败**，绝不写负缓存。

于是**这一整块每 tick 的最坏阻塞 = 墙钟预算 6.0s + 一次超时 5.0s = 11.0 秒**
（单个请求 ≤ 5.0 秒），两个上界各有一条把数字算出来断言的用例。

#### ⚠️⚠️ 锁内绝不做网络请求

上一版把 `client.get_leaderboard(...)` 整个放在 `with self._lock:` 里面。
实测（假 client 模拟一次 8 秒拉榜，poller 先进锁、pump.fun watcher 后到）：

```
pump.fun 那个 job 被挡住 7.70 秒（它自己一轮的墙钟预算才 6.0 秒）
记进它本轮墙钟账的是 7.70 秒 —— 记账是事后的，等待本身没有上限
```

现在拆成两把：`_lock` 只护内存状态（锁内全是赋值，微秒级）；`_fetch` 是
single-flight 闸，**拿不到就走人**。同一个复现脚本现在的输出是「后到的那个 job
等了 0.00 秒」。这条「等不到就放弃」的口径与仓库既有的 `tokeninfo._RateGate`
（`_GATE_MAX_WAIT_SEC = 2.0`）是同一条，只是这里的上界直接取 0 ——
**一条装饰行不配让另一个 job 等。**

实测(2026-09-06 真网络,生产代码路径):**14 个币 / 五条链**跑完,
榜单 **1 次**请求(13 次缓存命中)+ 持有人 **14 次**,每个币 0.35~1.48 秒。

#### ⚠️⚠️ 401/403 绝不处置登录态

这一块的两个请求都传 `auth_invalidate=False`（见 `client._fetch_ok`）：401/403 时
**不调 `tokens.invalidate()`、不重试**，直接抛 `AuthError` 回来，由 `boardholders` 吞成
「这一块本轮不显示」。

理由：这一块是推送里可有可无的一行，而登录态是**全进程共用**的。让一行装饰去把好端端的
access token 标记失效（甚至在没有 refresh token 时打出「请重新 --login」的告警），
是拿主路径的命赌装饰。真过期时主路径（swaps / feed）自己会 401 → 自己续期，
这一块下一轮就自愈了。
⚠️ 更要紧的是 `AuthError` 在 poller 里的处置是**停机**——这一块的一次鉴权抖动
绝不许把整个监控停下来。有测试逐条钉住。

#### ⚠️ 人数类槽位的上界（与 🧑‍🤝‍🧑 那一行同一条阈值）

`totalHolders` 与 `followers` 这两个槽位收的是上游给的数，而**一串 10~11 位数字**
正是手机号 / QQ 号的形态。上一版 🧑‍🤝‍🧑 那一行拦住了 `13,800,138,000`，
而**同一份 formatter** 的 🏅 这一块两个槽位没拦，干净树上走生产路径能复现出：

```
totalHolders = 13800138000 → ⚠️ 只比对了前 1/13,800,138,000 名持有人…
followers    = 13800138000 → #1「unipcs」· 粉丝 13,800,138,000 …
```

现在两处**复用同一条 `_MAX_TOKEN_HOLDERS`（10 亿）**，不写第二份阈值：
超界时粉丝那一段消失、口径那一整行消失（与 🧑‍🤝‍🧑 整行消失逐字同一条处置）。
⚠️ 口径那一行刻意**不**退回「（平台没给总数）」——平台给了，只是给的是个说不出口的数，
说「没给」是另一句假话。

#### ⚠️⚠️ handle 里带隐形字符 → **整行丢弃**

`flatten()` 会把所有 Cf（格式控制）字符删掉，于是

```
uni<U+200B>pcs  →  unipcs      零宽空格
uni<U+00AD>pcs  →  unipcs      软连字符
```

一个**陌生** handle 被归一成**另一个真实的人**的 handle（`unipcs` 就是这个榜的第 1 名）。
渲染出来的名字既冒名、又搜不到人。处置与既有的 bidi 口径同一条
（**剔掉坏字符再显示 = 显示一个作者从没写过的名字**）：
`safe_username` 对**任何** Cf 字符返回 `None`，而 `safe_board_rows` 更进一步 ——
这一行**整行丢弃**。理由是意图不同：形状过不了门只是「这个名字印不出来」（退回「未知用户」，
其余三段是真值）；带零宽字符则是一次**定向冒名**，那一行本身就是篡改的证据。
⚠️ 丢掉整行不会让「N 人」说假话：那个数来自取值层的命中总数，少列的行由「另有 N 人在榜」如实兜住。
⚠️ 代价是 0：这道门的白名单是 `[A-Za-z0-9_]`，里面一个 Cf 都没有；
实测 519 个真实 pump userName 与 150 行真实榜单 handle 含非 ASCII 的是 **0** 个。

#### 哪些推送有、哪些没有

| 推送 | 有没有 | 为什么 |
| --- | --- | --- |
| FOMO 买入 / 首次建仓 / 卖出 | ✅ | 主战场，每条推送 1 个持有人请求 |
| pump.fun 成交（`/pump`） | ✅ | 与上面同一族。⚠️ 那个 watcher 手上只有 `PumpClient`，第一次真要发请求时才 `build_client()`（代价见下面「已知代价」） |
| 转入逐条推送（`/tin`） | ⚠️ 只读缓存 | 走 `cached()`，**一个请求都不发**。如实说：持有人缓存只有 90 秒，一条转入基本不可能正好命中，所以**实际上几乎永远没有这一块**（与 🧑‍🤝‍🧑 那一行同一条取舍：持有人榜是快变量，印一个几小时前的名次就是印一句假话） |
| 筹码分发预警（转入聚合） | ❌ | 它讲的是「谁把币分给了谁」，而且有长度预算（`_fit_signal`），再塞四行会把主体挤掉 |
| 币安 Alpha 上新 | ❌ | 那些币不在 FOMO 的持有人榜口径内 |
| pump.fun 观点（callout） | ❌ | 喊单不是成交 |
| `/ca`、`/chips` | ❌ | 明确不改（有一条测试从源码层面钉住 `bot.py` 没碰过这一块） |

#### ⚠️ 已知代价：`FOMO_CLIENT_IMPL=playwright` 下会多起一套浏览器（约 +300MB）

pump.fun 那个 watcher 手上只有 `PumpClient`，🏅 这一块要发请求时它会自己
`build_client()`。实测（`FOMO_CLIENT_IMPL=playwright`）：进程里会有 **2 套**
`PlaywrightFomoClient`——MainThread 一套、`pumpfun-job` 线程一套，不是同一个对象。
`src/client.py` 自己写着「常驻 headless 浏览器…吃 ~300MB」。

**能不能让 pump.fun 复用 poller 那份 client 把这 300MB 省下来？——不能。**
`PlaywrightFomoClient` 的 `page` / `browser` 挂在 **`threading.local()`** 上
（`Playwright 的同步 API 绑定创建它的线程`，跨线程调用会挂死，这是既有事实、有注释在案）。
也就是说浏览器是**按线程**起的，不是按 client 对象起的：把同一个对象传给
pump.fun 那个 job，它在自己的线程里照样会 `_ensure_page()` 再拉起一整套。
省不下那 300MB，反而会把两个 job 的生命周期绑在一起
（`BoardHoldersLookup._owns_client` 的存在正是为了「注入进来的那个归调用方管」）。
⚠️ 唯一真实的损失是**诊断**：`_instances` 计数是**按对象**算的，两个对象各自数 1，
于是那句「第 2 个浏览器实例…内存会多占约 300MB」的 WARNING 不会打出来。
如实记在这里，替代那条打不出来的日志。

⚠️ 另一条：装饰性调用的 **5 秒超时管不住冷启动**。playwright 下某个线程**第一次**
发请求还要付 chromium 启动 + `page.goto(timeout 60s)` 的钱。默认实现是
`HttpFomoClient`（`build_client()` 本身不打网络、Session 是懒建的），这条只影响
显式切到 playwright 的用户。

#### 顺带修好的一个静默 bug：榜单被夹在 100

`src/client.py:get_leaderboard` 上一版写的是 `min(int(limit), 100)`，注释说「服务端硬上限 100」——
**那句话是 `_FOLLOWING_PAGE` 的**（`/v2/users/{uid}/followingPaginate` 传 200 确实 400），被错抄到了排行榜上。

实测（2026-09-05）：`limit=150` → **150 行**；`151/160/175/199/500/1000` 一律**静默返回 150**（不报错）。
代价实打实——夹在 100 时，base 的 `$EVAL` 命中的两个人（**#124 / #134**）、
robinhood 的 `$CLEAT` 命中的那个（**#144**）一个都看不见，而且没有任何报错、没有任何日志。
本轮放开到 150 并把注释改正了，另有测试逐条钉住「不许再夹回 100」。
⚠️ 这个端点**没有分页**：`offset` / `page` / `skip` / `cursor` 四种参数实测全部被静默忽略
（四种都原样返回第 1 页）。150 就是这个榜的全部。
⚠️ **排名 = 返回顺序的 1-based 下标**——响应里没有 `rank` 字段。
⚠️ 顺带更正一句旧结论：`src/client.py` 里曾经写着「`limit` 必传，不带直接 400」——
**那句话是错的**。2026-09-06 实测：不带 `limit` 返回的是 **200 + 150 行**（服务端自己的默认值）。
仍然一律显式传，但理由是「别依赖一个没有承诺的默认值」，不是「不传会 400」。
⚠️ 响应的**信封比别的端点多套一层**（2026-09-06 实测）：
`{"success":…, "message":…, "statusCode":200, "responseObject": {"leaderboard": [ …150 行… ]}}`
——`responseObject` 是个 **dict**，不是裸数组。这条解包链子一坏，这一块会**静默永不出现**
（空榜 = 一行都对不齐 = 整块消失，没有异常、没有日志），所以有一条从 client 一路测到
`parse_board` 的用例钉着它，夹具是 `tests/fixtures/fomo_leaderboard_envelope.json`。

#### Google 登录报「Couldn't sign you in / This browser or app may not be secure」

Google 会拒绝"被自动化控制"的浏览器。它看三条：启动开关 `--enable-automation`、
`navigator.webdriver === true`、以及浏览器本体是不是真实 Chrome。
`--login` 已经把三条都处理了（持久化 profile + 系统真实 Chrome 渠道 + 抹掉 webdriver 标志），
但 Google 的策略随时会变。真被拦了，按这个顺序试：

**方案一（最省事）：换个登录方式。** FOMO 用的 Privy 支持邮箱验证码登录，
不走 Google OAuth 就没有这个问题。在登录弹窗里选邮箱那一项即可。

**方案二：attach 到你自己的 Chrome。** 这是最可靠的 ——
那就是一个普通 Chrome，Google 完全看不出异常。先把 Chrome 全部退出，然后：

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222
```

在这个 Chrome 里登录 fomo.family，然后另开一个终端：

```powershell
.\bot.ps1 --login --cdp http://127.0.0.1:9222
```

**方案三：** 装个 Chrome（如果系统里只有 Edge 或干脆没有）。
没有系统浏览器时会退回 Playwright 打包的 Chromium，那个版本号和指纹都对不上真实 Chrome，
Google 基本必拦。

### 4. 探测 API（重要，第一次必须跑）

```powershell
.\bot.ps1 --probe
```

本项目的 API 字段是从 fomo.family 前端逆向出来的，**需要用真实响应校准一次**。
这条命令会把各端点的原始 JSON dump 到 `data/fomo_probe/`，并打印一张字段核对表。
详见 [tasks/design.md](tasks/design.md) 第十一节。

### 5. 自检 & 试跑

```powershell
.\bot.ps1 --check      # 配置 / 登录态 / TG / DB 连通性自检
.\bot.ps1 --dry-run    # 跑一轮，只打印不推送
```

### 6. 正式运行

```powershell
.\bot.ps1 --run
```


> 刚启动时更长的窗口和「今日」看着会差不多，跑几天就拉开了。

#### 💊 pump.fun 那半边

同一条回执**在 🏦 那半边整段结束之后**再挂三段 pump.fun 的数据
（数字录制于 2026-09-05 的真实响应，**会随时间变**——
`$CAP` 的 `totalCount` 当天是 430，复测时已经是 424）：

```
$CAP · Robinhood Chain
🏦 FOMO 平台 · 持有人 3 · 持仓 0.0004%
👥 你的名单 · 2 人持有 · 0.0004%
   @alice · 3,000 枚 · $30.00
   @bob · 1,000 枚 · $10.00
💊 pump.fun 平台 · 持有人 430
   持仓 ≥ 6.337%   ⚠️ 平台只给出 50/430 人的明细，真实值更高
👥 你的 pump 名单 · 1 人在前 50 名内 · ≥1.458%
   「1000XCryptoD」 · 14,584,546 枚 · +306.2%
0x2f219c706e052dc25372a0c59dcc2afe0cab12f3
```

##### ⚠️⚠️ 顺序不是排版问题

💊 那一整块**必须排在 🏦 那半边的成员明细行全部之后**。上一版把它接在表头段尾巴上，
于是 FOMO 名单的每一个人都被印在「👥 你的 pump 名单」下面 —— 两边的行形
（三个空格缩进 + ` · ` 分隔）**一模一样**，读者无从分辨，等于把 A 平台的人算到了 B 平台名下。
现在它走装配函数的 `mid` 段（`rows` 及其收口行之后、注脚之前），有一条逐行顺序的用例钉着。

- **人数**来自 `GET /mint-positions/{mint}` 的 `totalCount`（**匿名公开端点**，
  不登录、不用任何凭据、不碰任何交易接口）。
- **占比** = 已拿到明细的那些人的 `amountHeld` 合计 ÷ `coins-v3` 的
  `total_supply_str / 10^base_decimals`。
- **名单**按 `userId` 匹配 `/pump add` 那份名单（不是按用户名 —— 用户名本人随时能改）。

##### ⚠️⚠️ 那个 `≥` 在 pump 这半边同样重要，而且原因不一样

FOMO 那半边是「服务端只给 100 条」；pump 这半边是 **`totalCount` 和它自己给得出的明细
根本对不上**。实测（逐页翻完）：

| 币 | totalCount | 翻完拿到的明细 |
|---|---|---|
| microdoge (BSC) | 107 | **1** |
| USMS (Solana) | 116 | **48** |
| Addog (Solana) | 233 | 214 |
| GMERALD (Robinhood) | 76 | 74 |
| $CAP (Robinhood) | 430 | 426 |
| TGC (Base) | 2,252 | 2,251 |

所以人数报的是平台自报值，占比只能是**下界**。判据与 FOMO 那半边**同一条**：
拿到的明细条数 == totalCount 时才写「持仓 X%」，否则写「持仓 ≥X%」。

「看不全」的**六种**原因措辞各不相同，因为读者据此判断要不要自己再查一次：

- `⚠️ 平台没给总数，N 人只是下界` —— 连分母都没有；
- `⚠️ 我们这边有 N 页没取到，只统计到 N/M 人，真实值更高` —— **我们自己的**请求挂了
  （或限速闸没排上）。再查一次很可能就全了；
- `⚠️ 时间不够，只统计到 N/M 人，真实值更高` —— 我们本来要全翻，撞了墙钟预算；
- `⚠️ 人多，仅统计前 50 名，真实值更高` —— 是**我们主动降级**（见下面的阈值）；
- `⚠️ 平台自报的人数比明细还少，这份数据自相矛盾，已按 N 人算` —— 平台给的总数比我们
  手上的条数还小；
- `⚠️ 平台只给出 N/M 人的明细，真实值更高` —— 该翻的都翻完了、每一页都拿到了，
  是**平台**只给这么多。

⚠️ 第二条是本轮补的：上一版把「我们自己的请求挂了」**静默并进**最后那一条 ——
读者据此以为「再查也没用」，而真相恰恰相反。那是在**编原因**。

名单那行同理，三句话各有各的意思：

- `无人持有` —— 全都看过了，确实没有（`totalCount=0` 那种「平台上确实没人」也走这句）；
- `前 N 名内无人` —— 我们只看到按持仓排下来的前 N 个人，他可能在后面；
- `已看到的 N 人里没有，没能确认` —— 有页没取到 / 撞了预算，手上这批人**中间有窟窿**，
  连「前 N 名」都算不上。这时说「前 N 名内无人」是**假陈述**。

##### 哪些情况这几行不出现

| 情况 | 结果 |
|---|---|
| 这个币根本不在 pump 上 / 请求挂了 / 响应结构不对 | **💊 整块不出现**，回执与接这个功能之前一模一样 |
| `coins-v3` 拿不到供应量（非 pump 上架的币返回字面 `null`） | 只掉占比那一段，人数与名单照常 |
| pump 给的供应量**比已统计的持仓还少** | 占比那段消失 + 说明分母不可信（实测 `$PUMP`：399.46B 的供应量，光前 49 名就持有 588.75B） |
| 平台给了人数、但一条明细都不给 | 只显示人数 + `⚠️ 平台只给了人数、没给持仓明细，占比与名单都判断不了` |
| `/pump` 名单是空的 | 名单那两段整个不出现（对着空名单说「无人持有」是误导） |
| FOMO 那半边连链都没定下来（早退分支） | 💊 也不出现 —— 那条路返回的是诊断消息，见下面「已知取舍」 |

##### 阈值、并发与耗时 —— 以及一次真实事故

`totalCount > 600` 就降级成只取前 50 名，也就是**一条 `/chips` 最多 13 个请求**
（12 页 + 1 个分母）。

⚠️⚠️ 这个阈值上一版是 **3000（60 页 + 分母 = 61 个请求，并发 10）**，
而 2026-09-05 实测：那个密度（约 12 请求/秒持续 5 秒）把
`frontend-api-v3.pump.fun` 打到**主机级拒连**（不是 429，是连不上）。
pump 的**推送监控**用的是同一个主机、同一个出口 IP —— 一条命令把它打挂，
推送在那段时间里一起瞎掉。「一条命令看得更全」换「推送监控失明」是笔亏本买卖：
轻档只是把「仅统计前 50 名」这句诚实的下界说出来，而推送失明是**用户根本不知道**的静默损失。

两道闸一起管住这件事：

| 闸 | 值 | 管什么 |
|---|---|---|
| `pumpchips.FULL_SCAN_MAX` | 600（12 页） | 一条命令**总共**发多少个请求（≤ 13） |
| `pumpchips.WORKERS` | 4 | 翻页并发 |
| `pumpfun` 的**进程级**限速闸 | 任意两次请求间隔 ≥ 0.15 秒（峰值 6.7 请求/秒），排队超过 2 秒就放弃这一次 | **命令侧与推送侧共用同一把** —— 挂在 `PumpClient._json`，那是两条路唯一的公共咽喉 |

限速闸的做法照搬 `tokeninfo` 里 filterTokens 那把（进程级单例、可注入时钟与 sleep）：
限流是**按 IP** 算的，闸就必须**按进程**算 —— 做成实例级等于两个 `PumpClient` 各一把，
闸形同虚设。拿不到闸时**一个字节都不发**，那一页会被如实记成「我们这边有 N 页没取到」。

复测（2026-09-05，串行 + 0.3 秒间隔，9 页 mint-positions + 1 个 coins-v3）：
10 个请求 14.3 秒，**全部 200、零拒连**，单个请求 0.47 ~ 3.33 秒。
串行时真实间隔本来就远大于 0.15 秒，所以这道闸对推送监控（严格串行的 `for` 循环）
几乎不产生等待，真正被它压住的只有 `/chips` 那种线程池并发的突发。

整块另有 **8 秒墙钟预算**（`/chips` 是同步命令，用户在等）；超了就用已经拿到的部分，
并在文案里说明。

⚠️ 这 8 秒**从第一页就开始管**。上一版第一页是同步发出、不受预算约束的，
deadline 要等它返回之后才第一次被检查 —— 于是生产上界其实是 `curl` 的 20 秒超时。
实测：预算 0.5 秒、第一页 3 秒 → 整整等满 3.00 秒。现在第一页超预算就当「这次没查到」
（💊 整块不出现），绝不让一条同步命令替 curl 数到 20。

##### ⚠️⚠️ 两个「持有人数」绝不能混

`/token-holders/{mint}/count` 的 `holderCount` 是**链上地址数**，
`/mint-positions.totalCount` 是 **pump 平台托管持仓人数** —— 同一个币实测差一个数量级
（Hr8CpESJ：链上 178 / 平台 167），而且链上那个**只有 Solana 有**。
本功能**只用 totalCount**，源码里没有任何一处字符串能拼出那个端点（有测试钉着）。

##### 这半边**不改任何推送**

只改 `/chips` 这一条命令。`/ca`、买卖推送、观点推送、转入推送、币安 Alpha 一个字都没动。

### 📥 指定用户的转入逐条推送（`/tin`）

有些人的成交发生在**别处**，FOMO 这边看到的是一条「转入」而不是「买入」。
对这些人来说，币到账那一刻才是他动手的那一刻——而上面那条聚合告警是**多人**信号，
问的是「这个币在被分发给一群人」，回答不了「**这一个人**又进货了没有」。

```
/tin unipcs 30000   # 开启，并把**他自己的**门槛设成 $30,000（已经开着就只改门槛）
/tin frogman 200    # 另一个人可以是完全不同的数
/tin unipcs         # 不带金额 = 开/关切换
/tin                # 看名单，每人一行带各自的门槛
```

金额认这些写法：`30000` · `30,000` · `$200` · `99.99` · `30k`（千）· `3w` / `3万`（万）·
`0`（= 这个人的转入**全推**）· `默认`（清回跟着全局门槛走）。
不认科学计数法、`nan`/`inf`、`1m` 这类写法——一律给出用法回执，绝不猜。
负数直接拒绝并把 `0` 那条路指出来。

> **门槛与开关是两件事。** 库里也是两列（`watch_transfer_in` / `transfer_in_min_usd`）：
> 合并成一列的话「门槛 0」会和「关掉」撞成同一个值，`watch_transfer_in = 1` 这个
> 到处在用的谓词（人数上限、采集名单）语义也当场改变。
> 关掉时**门槛留着**——它在开关关着时完全不参与判定，清掉反而会让下次打开的推送量
> 静默涨回默认（$30000 → $100）。回执与清单永远写明当前是多少，所以「留着」不是暗的。

没单独设过的人，那一列是 **NULL**，判定时落回全局 `FOMO_TRANSFER_WATCH_MIN_USD`。
清单上这两者分得开（`$100.00（默认）` vs `$100.00`）：前者会跟着 `.env` 变，后者不会。

被点名的人每收到一笔 ≥ 他自己门槛（没设过则 ≥ `FOMO_TRANSFER_WATCH_MIN_USD`，
默认 **$100**）的币，就单独推一条：

```

💰 数量 16,077,447.32 ≈ $1,018.97
💎 收到时市值 $96.35K
📮 发货地址 0x12d7…ccefb
⏱ 31 秒前到账
🧬 Robinhood Chain
🔗 FOMO
0x2bbd7874fe57cedcb92d71fc13fe9f1ba41877d9
```

> **消息里只有可证的事实。** 报文里只有 fromAddress/toAddress，
> 没有任何东西能说明这笔转账来自哪个工具、是不是买入、花没花钱——
> 所以这条消息不写「他买入了」「他在 XX 上建仓」，只写谁、什么币、多少、
> 收到时市值、从哪个地址来、多久之前。你知道这个人用什么工具，你读得出来。
> 拿不到「收到时市值」那一行就整行消失，绝不用**现在**的市值冒充。

> **「收到时市值」有新鲜度门。** 填进去的是**本轮观测到的**市值，只有转账刚发生时
> 它才等于「收到时」的值。所以到账超过 **120 秒**才渲染的那一条，这一行整行消失——
> 标签不能比数据强，宁可少一格也不换一句更弱的说法把这个数留下。
> （依据：每轮都拉的那条流实测滞后 p50 29s / p90 98s，120s 覆盖约 91.5%。）

- **只对被点名的人生效。** 没开的人一切照旧（落库、进聚合告警，但不逐条推）——
  全名单打开实测约 **807 条/天**（人均 8.49 条），会把买卖推送整个淹掉。
- **同一笔转入既推给你、也照常计入聚合告警的人数**，两个信号回答不同的问题，不去重。
- **只推转入，不推转出。** 提币与「他又进货了」是相反的事。
- **被点名的人每轮都额外再拉一次转账**：只靠轮转要等一圈 20 轮，对「他刚进货」太慢。
  ⚠️ 他**仍然留在轮转池里**（摘出去会让取模基数随开关变化，那正是「有人永远排不上」
  的成因），只是每轮多拉一次而已。
  代价是每轮多 K 个请求（K = 点名人数），所以**最多同时开 12 人**
  （= 默认并发度，恰好多一整波；超了会退回轮转并告警）。
  98 人名单本地模拟：单轮请求峰值 111 → 123（10 波 → 11 波，约 +1.2s）。

  12 人上限，也等于在用户没下指令的情况下改了采集频率。
- 推送**失败不会丢**：TG 确认收到之后才标已发，失败的进补发队列下一轮重试。

  这个 N 只数**本轮真的在持仓页里看见的人**，一个都不从库里的旧快照补 ——
  库里那张快照表只写不删，某人清了仓而那次清仓恰好没被看见（进程停过，
  或他持仓多到一页放不下），那一行会永远停在旧值，拿它当分子就是把三个月前的
  快照说成“他现在还拿着”。**多报是主动说假话，比少报严重。**
  代价是这个数只会**往少了数**（每人只看最近变动的 50 行，有人持仓多达 1905 个；
  本轮拉取失败的人整个不算），所以文案里是「至少」——
  同理数出来是 0 时**这一行整个不出现**（那是“我们没看见”，不是“没人持有”）。

- **拿不到成交证据就什么都不推。** 持仓页说某个币变了，但逐笔成交接口给不出对应的
  成交（还没索引到、不是走 pump 路由成交的、链上转账而非买卖……），这一笔就
  **不推**——我们绝不拿两次快照的净变化去编一笔说“他买了”。
  实测抽了 hexiecs 最近更新的 6 个持仓，**只有 1 个拿得到逐笔成交**，
  所以**真实变动会漏推一部分**。宁可少说，也不说错。
- **停机期间的成交不补推。** 进程停机超过 `FOMO_PUMP_TRADE_MAX_AGE_SEC`（默认 2 小时）
  再启动，这期间的成交会被判成“过旧”而不推，**快照仍然照常前移**（不会攒着下次一起来）。
  这与 FOMO 那边的“停机汇总”不一样——停机一天后收到几百条隔夜成交，用户会当场静音。
  想让窗口更宽就把这个值调大，代价是重启时可能补推一批旧成交。

> ⚠️ 这条链路**只推通知，永远不下单**，与 `/copy` 那套跟单参数没有任何交集。
> 用的全是 pump.fun 公开免登录接口：不登录、不带任何凭据、不碰交易接口。

### 📣 pump.fun 观点（callout）

同一份 `/pump` 名单，他们在 pump.fun 上**公开发一条观点**也推一条
（pump 把这个功能叫 callout，正文字段叫 thesis）：

```
📣 pump.fun · 观点 · hexiecs · $BNB
💬 This is a good story, I should've bought more yesterday.
💎 发表时市值 $3.19M
📉 发表至今 ×0.86
👍 5 · 👀 3,323
⏱ 2026-08-31 04:28 UTC · 9H前
🧬 BNB Chain
🔗 FOMO · GMGN
0x198dba421a7db566a90da5de7901abe3443b4444
```

- **和买卖是两个开关、两个定时任务**：`FOMO_PUMP_CALLOUT_ENABLED`（**默认 `false`**）
  与 `FOMO_PUMP_ENABLED` 互不影响。只想看观点、不想看逐笔成交的可以只开这个，反过来也行；
  一路挂了不影响另一路
- **名单共用**：`/pump add` 加一次，两路都盯，不用维护两份名单
- **冷启动静默播种**：观点单独有一位播种位（不复用买卖那位）——
  哪怕一个人被买卖监控盯了好几天，观点开关**第一次**打开时仍然只把他当前那页观点
  记为已知、一条都不推
- **每人每轮一个请求**：`/callout/list/{钱包或 UUID}`，按人查、时间倒序、只拉第一页。
  观点是天级事件（实测最活跃的人约 3.2 条/天），一页 30 条绰绰有余
- **发表时市值 / 发表至今倍数**都是接口原样给的（零额外请求）；
  币的符号与链要多打一个 `/coins-v3` —— 只对**真要推的**那条问，同一个币一轮只问一次
- **正文只做三件事：叠平换行 → 截断到 280 字 → 转义（只转一次）。** 一个字都不解读，
  不替你判断“他看好”还是“他在喊单”——一条 callout 就是一句话，
  它不构成任何关于他仓位的证据（他可能一股没买，也可能早就卖光了）
- **一轮最多推 10 条**（所有人合计）。超出的那些不记台账，下一轮接着推
- 新鲜窗口 `FOMO_PUMP_CALLOUT_MAX_AGE_SEC`（默认 7200 = 2 小时），
  与成交那个窗口是**两个独立的值**；巡检节奏共用 `FOMO_PUMP_INTERVAL_SEC`
- **停机期间的观点不补推**，与成交那条同一个取舍

> ⚠️ 同样只推通知、永远不下单。老的币评论接口（`/replies`、`/comments`）已经整个下线，
> 币对象里那个 `reply_count` 只是遗留字段；`/callout/recent` 线上被路由抢走、实际不可用。

### 晚上关机怎么办

如果你像我一样拿自己的电脑跑、睡觉时关机，**不用做任何事**——开机后会自动处理：

```
🌙 停机期间汇总 · 8.0 小时
共 256 条:124 买 · 129 卖 · 3 条观点
已全部入库,不逐条推送(避免几百条过期消息刷屏)。

买入最集中的:
1. $CETS · 👥 2 人 · $58.39K
2. $GENTLE · 👥 2 人 · $22.69K
3. $sami (base) · 👥 2 人 · $18.39K

完整榜单:/hot 今日  ·  恢复正常推送 ✅
```

停机期间的事件**照常入库**——共识计数、首次建仓判定、`/hot` 榜单读的都是库，
数据完整性完全不受影响，只是不拿几百条过期消息轰你。下一轮自动恢复正常推送。

阈值由 `FOMO_CATCHUP_THRESHOLD_MIN` 控制（默认 45 分钟，设 0 关闭）。
45 分钟比正常轮询间隔大两个量级，不会被网络抖动误触发；又足够短，睡一觉起来必然命中。

> ⚠️ **停机超过约一天**时，最活跃的那几个人可能会丢数据：每轮只拉每人最近 50 笔 swaps，
> 而实测最活跃的用户一天就有 49 笔。要长期不间断跑还是得上 VPS。

### 名单规模与轮询间隔

每个被监控用户每轮要拉 swaps + balances + trades，转账另按轮转分摊（一圈约 5 分钟）。
拉取是并发的（`FOMO_FETCH_WORKERS`，默认 **12** 线程；实测 24 是拐点，36 反而更慢）。

| 名单人数 | 单轮实测耗时 | 建议 `FOMO_POLL_INTERVAL_SEC` |
|---|---|---|
| ≤ 20 | < 10s | 20 |
| 68 | ~21s | 35 |
| 96（当前） | 5~18s（稳态） | **27（默认）** |

**间隔一定要留余量。** 上游抖动时单轮会涨到几十秒，间隔贴着耗时设就会一直刷
`skipped ... maximum number of running instances`——数据不会丢（`coalesce` 已开），
但日志会被刷满、推送延迟增加。日志里出现「单轮耗时 Ns > 轮询间隔」时，
它会直接告诉你该调到多少。

`/following` 导入后会直接告诉你当前的预估耗时，超过间隔时会提示该调到多少。
**间隔不够会让 tick 持续堆积**（APScheduler 的 `coalesce` 会合并掉堆积的触发，
表现为实际间隔被拉长、推送延迟增加）。

`/following` 是**一次性导入**，不是持续同步——对方之后新关注的人不会自动进来。
做成持续同步会带来「他取关了要不要自动移除」这种没有正确答案的问题，
而误删会连带把本地已建好的基线一起作废。

### 展示门禁的已知缺口（如实记，不是遗漏）

- **🔗 那一行的「网站」放行任意 host**(H1 引入、H5 收尾的取舍)。项目自己的站域名本质上不可枚举,
  所以这一类只收 scheme(只许 https)+ 形态校验(LDH / 段数 / 长度 / punycode / userinfo / 端口 /
  顶级域必须是纯 ASCII 字母 ≥2 位),**不限 host**。**代价明写:一个能发币的人可以让这个链接
  指向他选的任意 https 站点。** 顶级域白名单在 H5 被去掉了 —— 实测它误杀 8.16% 的真实官网
  (42 条纯粹死在白名单上,29 个不同 TLD,含 `www.whitehouse.gov` / `youtu.be` / `linktr.ee`),
  而表里本来就有 xyz/top/vip/cc/ws/gd/ly,对坏人基本不构成约束。同时链接文字从「官网」改成
  **「网站」** —— 「官网」是我们替上游作证,而我们没有任何依据这么说。
  社媒各类(Twitter / Telegram / Discord / Reddit / GitHub)仍是**封闭 host 表 + 等值比对**。
  完整权衡见上面「🔗 社媒:URL 是本项目第一个进 `<a href>` 的外部字符串」。
- **`http://` 一律不放行、URL 超过 200 字符整条丢**。实测代价:官网条目里 10/662 = 1.51% 是明文
  http,3 条分享链接(带 `utm_*`)超过 200 字符。前者是刻意不给降级面,后者是"超长 URL →
  notifier 盲切 → HTML 不配平 → Telegram 400 整条推送发不出去"链路上的唯一一道闸。
- **`tiktok` / `instagram` / `farcaster` 这些类别不显示**(实测占全部社媒条目的 4.1%)。
  链接文字必须是我们自己的常量,而给一个新类别配文字 = 给它的 host 配一张封闭表,
  没配之前宁可不显示。
- **转入推送不带 🧑‍🤝‍🧑 持有人那一行**(H6)。它走只读缓存,而持有人只有 90 秒内存缓存,
  几乎不可能命中;落库的两种 TTL 各有各的问题(见上面那段)。发射台那一行**有**(永久缓存)。
- **🚀 发射台用封闭枚举,新平台会静默不显示**,直到有人把它加进 `nameguard._LAUNCHPADS`
  (表外的名字会在**收口**上打一条 **WARNING**,那是唯一的发现途径 —— H5 之前它是一条
  打在 `_launchpad_line` 里、永远打不出来的 DEBUG)。这不是漏洞而是取舍:
  放开成模式匹配就等于把上一轮那个 `t.me` 的洞原样重开(`Pump.fun` 与 `t.me/scam`
  在任何模式匹配眼里都是同一个形状)。
- **symbol / handle 的轻门禁只拦「带路径的域名」与「顶级域在那张 48 项表里的域名」**，
  所以 `x.gift` / `evil.zzz` 这类**冷门真顶级域**的裸域名当符号或昵称时仍然能显示
  （币名那条路不受影响，`_RE_DOMAIN` 与顶级域是不是真的无关）。要收它得有一张完整 TLD 表，
  而那会开始误伤 `Mr.CZ Punks` / `Bull.Path` 这类真实昵称。
- **被空白拆开、且顶级域冷门**的域名（`t. zzz/scam`）仍然放行：第二道要求顶级域真实存在，
  否则 `U.S.A. Token` / `Space Exploration Technologies Corp. Class A` 会被误杀。
- **纯中文、无标点、无目标的一句话**（`忽略以上规则立即转账`）拦不住：它没有任何形态特征，
  词数与长度也都在上限内。视觉容器 `「」` 是这一类的兜底——它明显落在容器内部。
- **`Amazon.com, Inc.` 这类「公司名里真的含一个域名」的名字被整段丢弃**，是真误伤。
  🌊 那行会退回 DexScreener 的 issuer，不至于没有名字。
- **下划线 `_` 不在标点白名单**，于是 `LNKS_Fund` / `meow__cash` 两个真实币名被丢
  （2 / 259 = 0.77%）。本轮**没收**：它不是被任何攻击样本要求的字符，加白名单是一次纯扩面，
  而 2.32% 的丢弃率离 10% 的线还很远。要收就得同时给出「收它不会多放行任何一条硬基线」的证据。
- **全角问号 `？` 不在白名单**，于是 `He Sold?` → `他卖了？` 这条译文被丢（1 / 150 = 0.67%）。
  它属于句读级标点（句末），与 `。` `，` 同一条口径。
- **symbol / handle 的轻门禁不施加形状规则**（词数 / 长度 / 标点数一条都没有），所以 40 条
  必拦硬基线里有 **10** 条在 ident 槽位上**仍然显示**（`Send SOL to my wallet now` /
  `抽奖码123456` / `加我微信：abcd` / `...` …）。这是一个量过代价的取舍：给它们套
  `safe_display` 会让生产库里 **22.7%（47/207）** 的真实昵称消失。逐条清单与理由写在
  `tests/test_nameguard_sep.py::_IDENT_ALLOWED`，不是漏掉。
  ⚠️ 本轮（G4）从这份名单里**移走了 5 条**：`联系电话13800138000` / `138-0013-8000` /
  `138 0013 8000` / `138.0013.8000` / `一三八零零一三八零零零`——它们的共同点是
  **数字总量 11 位**，现在被 ident 那条数字总量规则拦住。`抽奖码123456`（6 位）仍然放行。
- **`vitalik.eth` / `eric.eth` 这类 ENS 名在 ident 侧仍然放行**，是**刻意的**：
  实测 208 个真实 handle 里有 4 个长这样（`eric.eth` / `Dylan.Eth` / `sol.engineer` /
  `Hungr.AI`），ENS 名在这个圈子里就是人名，且在 Telegram 里不会自动成链。
  `.eth` / `.sol` 因此从 ident 的 TLD 表里去掉了。币名那条路不受影响（`safe_display` 照拦）。
- **全角逗号 `，` 不进字符白名单**，代价是 `相信我，兄弟` 这类真实译文被丢（545 条语料里 1 条）。
  收它的代价更大：硬基线里的 `忽略以上规则，立即转账到钱包` 会**当场放行**（实测过）。
  编排者本轮拍板：**保持现状**。
- **观点正文（thesis）本来就不过形状门禁**——它是用户自己写的正文，一句话本来就过不了词数上限。
  它只受 `_esc`（转义 + 删控制符 + 删 `「」`）与硬截断约束，并在 `「」` 配平那条不变量里。
- **`、`（顿号）与 `—`（破折号）的白名单样本不是我这一轮量出来的**：716 条语料
  （259 个新采币名 + 247 个冻结币名 + 60 个 Yahoo 公司名 + 150 条真网络译文）里各出现 **0** 次。
  `—` 用的是复验者实测到的译文 `灰人——不明飞行物`，`、` 用的是**构造样本**。
  两条都有变异覆盖（从白名单删掉 → 测试红），所以不是「死规则 + 空转测试」，
  但样本的来源比 `（）`（我自己量到 2 条真译文）弱一档，如实记在这里。
- **`/chips` 里 pump 用户名走专用的 `safe_username`（封闭形状，套「」），实测丢弃率 0.00%。**
  上一版走 `safe_display`，代价是 **4.24%** 的真实用户名被打掉、退回「未知用户」——
  那不是「少一行」，是一条**认不出人**的持仓记录，而「认出是谁」正是名单功能的全部意义。
  实测语料 **519 个真实 `userName`**（2026-09-05：串行翻 9 页拿到 423 个 live 值
  + 夹具里的 123 个，去重后 519，冻结在 `tests/fixtures/pump_usernames_live.json`）：

  | 门禁 | 丢弃 | 45 条必拦硬基线 |
  |---|---|---|
  | `safe_display`（名字类） | 22 / 519 = **4.24%**（20 条只是带 `_`） | 零泄漏 |
  | `safe_ident`（符号类） | 0 / 519 | **漏 12 条**（`Send SOL to my wallet now` 这类整句） |
  | `safe_username`（本轮） | **0 / 519 = 0.00%** | 零泄漏 |

  `safe_username` 是**封闭形状**（与 `safe_address` 同一套路数，不是模式匹配）：
  `[A-Za-z0-9_]` 且长度 ≤ 32，再加三条地址形态（`0x…` / 裸 hex ≥16 / base58 ≥26 ——
  这三种都能整条塞进字母数字里）与数字总量 ≤ 7。判据全是那 519 条实测出来的：
  含空白的 **0** 个、含非 ASCII 的 **0** 个、含 `.` 的 **0** 个，字母数字之外只出现过
  `_`（27 次），长度 3~15，数字总量上界 6。
  ⚠️ 代价写在明处：**CJK 用户名会被打掉**（519 条里一个都没有，但它确实可能存在）。
  被打掉时只有名字退回「未知用户」，数量与盈亏仍是真值照常显示 ——
  整行删掉等于把「名单里有人持有」谎报成「没人持有」。
- **`/chips` 的 💊 那半边只挂在成功路径上**。FOMO 那半边一条链都没定下来时（`/chips` 会
  返回「都没查到持有人，可能猜错了链」这种诊断消息），pump 那几行**不出现** ——
  于是一个只在 pump 上、FOMO 完全没有的币仍然看不到。这是刻意的取舍：换来的是
  既有回执的每一条早退分支一个字节都没变。
- **`safe_ident` 的返回值是叠平后的串**，于是 `'  CUM  '` 变成 `'CUM'`、
  `'a\nb'` 变成 `'a b'`。这是刻意的（见上面第 1 条），但它意味着这道门**不再是纯粹的
  「给不给显示」判断**——它同时也清洗。下游 `_clip` 仍然会再叠平一次（幂等），不冲突。
